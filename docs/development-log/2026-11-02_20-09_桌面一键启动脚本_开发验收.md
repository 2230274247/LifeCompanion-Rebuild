## B. 目标与范围

原项目启动需要分别处理 Docker 容器、`life-core` 和 3001 网关，用户操作步骤多。
本次在桌面生成 `C:\Users\Administrator\Desktop\启动拾光.cmd`，双击后自动：

1. 检查 Docker，必要时启动 Docker Desktop；
2. 启动 LibreChat、Memos、MongoDB、MeiliSearch 容器；
3. 仅在健康检查失败且端口空闲时启动 `life-core` 与统一网关；
4. 等待四个服务健康检查通过，再打开 http://127.0.0.1:3001。

明确不包含：删除/重建数据库、停止已有健康服务、重新构建前端、部署公网、
自动登录账号或修改用户数据。若目标端口被未知进程占用，脚本拒绝误杀并提示检查。

## C. 架构与实现

桌面 `.cmd` 只负责稳定地调用版本化 PowerShell 启动器：

```text
桌面 启动拾光.cmd
  → scripts/start-lifecompanion.ps1
      → docker info / Docker Desktop
      → docker compose baseline + spa overlay
      → 8010 life-core（仅缺失时）
      → 3001 Node 网关（仅缺失时）
      → 5230 / 3080 / 8010 / 3001 健康检查
      → 默认浏览器打开统一入口
```

- `.cmd` 使用纯 ASCII 与 CRLF，避免 Windows 命令解释器受 UTF-8 无 BOM 和 LF
  换行影响。中文启动进度由 PowerShell 输出。
- PowerShell 脚本保存为 UTF-8 BOM，兼容 Windows PowerShell 5.1 对中文源码的读取。
- 本机服务使用隐藏窗口启动，标准输出/错误分别写入
  `infra\runtime\launcher-life-core.*.log` 和 `launcher-gateway.*.log`。
- Compose 参数固定为 `compose.baseline.yaml` 与 `compose.spa.yaml`，不调用
  `down -v`、不升级镜像、不修改容器数据。
- 启动器读取既有本地 `.env` 到子进程，不输出密钥。健康服务直接复用，
  不因重复双击产生重复进程。
- 前端不需要重新构建；现有 Express HTML 缓存注意事项不变。

## E. 功能结果

用户双击桌面“启动拾光.cmd”即可启动完整本机环境，成功后窗口提示可关闭，
浏览器自动打开统一入口。再次双击会识别现有健康服务，不会重复启动。

失败时保留窗口并提示查看 `infra\runtime\launcher-*.err.log`。脚本不会为了抢占
3001/8010 而停止未知进程。已有 Docker、容器、数据库和 V0.2 前端构建均复用。

### 失败与修复

1. 第一次 PowerShell 启动器文件为 UTF-8 无 BOM，Windows PowerShell 5.1
   将中文源码误读并产生语法错误；真实复现后改为 UTF-8 BOM，语法检查通过。
2. 第一版桌面 `.cmd` 为 UTF-8 无 BOM、LF 换行，CMD 将连续命令拆坏并报
   “系统找不到指定的路径”；改为纯 ASCII、CRLF 后重新冷启动通过。
3. 非交互环境中的 `timeout` 曾输出输入重定向错误；保留实际等待但重定向其错误输出，
   最终命令行退出码为 0。
