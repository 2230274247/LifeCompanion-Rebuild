## 2. 目标与边界

原问题：用户希望把 murmur 的玻璃球作为“浏览器旁边的小宠物”，需要透明、无边框、
置顶、不占任务栏、可随时隐藏的常驻窗口。用户在选项中选择了 Tauri 置顶窗。

实施中出现两个硬条件：

- Tauri 的 Windows 构建需要 MSVC 链接器和 Windows SDK。本机
  `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools` 只装了半套，
  有 `link.exe` 但没有 Windows 10/11 SDK 的 `Lib`；`cargo build` 实测失败。
- `C:` 盘 179GB 中仅剩 **2.8GB** 可用，补装 Windows SDK（约 1.5GB）后余量过小。

经用户确认，改用 **Electron**：不引入编译器，依赖装到 `H:` 盘，代价是运行时常驻内存更高。

计划：Electron 外壳 + 复制 murmur-web 源码；透明置顶小窗；托盘与右键菜单；
位置记忆；点击状态反馈。

明确排除：不接入 Life Companion 的聊天/提醒状态；不做安装包、开机自启、
多物种切换界面；不在本轮做位置拖拽与鼠标穿透的实测。

## 3. 架构实现

三层，边界刻意保持最小：

- **主进程** `electron/main.cjs`：创建 260×260 透明无边框窗；`alwaysOnTop: 'floating'`；
  `skipTaskbar`；单实例锁；窗口位置写入 `userData/pet-window.json`；托盘与菜单。
- **预加载** `electron/preload.cjs`：只通过 `contextBridge` 暴露 `showMenu()`，
  转发一个 IPC 消息，不暴露 Node、文件系统或任意 IPC。
- **渲染层** `src/main.ts`：一个 `Murmur` 实例（`aura`）、点击状态机、视差、右键菜单触发。

窗口参数：`frame: false`、`transparent: true`、`backgroundColor: '#00000000'`、
`hasShadow: false`、`resizable: false`、`skipTaskbar: true`、
`alwaysOnTop: true`，并用 `showInactive()` 避免抢焦点。渲染层
`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`，
页面含 CSP，只加载本地构建产物。

视觉：murmur 的 present pass 输出 alpha 恒为 1，画布必然是不透明矩形，因此用
`border-radius: 50%` 裁成圆，再用径向 `mask-image` 柔化外缘；`formScale: 1.5`
让玻璃球填满气泡，`ink: '#141120'` 把底色从纯黑抬成深紫。这些都在本地下游完成，
未修改上游源码。

murmur 集成：按上游 README 的“复制源码”方式引入
`krispuckett/murmur-web@501edfbac594b06a20cb3ca92bdf4c7a19840717`（MIT，69 个文件），
运行时依赖 `vgpu@0.3.1`；`@vgpu/wgsl@0.3.1` 仅构建期使用。
`fps: 30`、`resolution: 0.8`、`maxPixelRatio: 1.5` 用于压低常驻 GPU 成本。

交互：单击球体依次进入 `listening → thinking → responding → success`，2.6 秒后回
`idle`；拖动球体写入 `tilt()`；窗口留白使用 `-webkit-app-region: drag` 拖窗；
右键与托盘共用同一份菜单。

## 5. 功能结果

已完成并实测：

- 透明、无边框窗口正常启动，玻璃球在桌面右下角渲染。
- 窗口位于当前活动窗口之上，截图时 Codex 在前台而宠物仍可见。
- 任务栏没有宠物按钮（`skipTaskbar`）。
- 单击球体切换到下一状态，截图对比可见材质变化。
- 右键球体弹出菜单：总在最前、鼠标穿透、回到右下角、重新载入、退出。
- 托盘对象创建成功，菜单与右键共用；再次运行启动脚本不会产生第二个实例。
- 构建产物 697KB JS（gzip 151KB）；启动日志为空（仅一个换行，无报错）。

未完成或未验证：

- 拖动窗口、位置恢复、鼠标穿透三项只有实现，**未实际验收**。
- 没有安装包与开机自启，只能通过 `scripts/start-pet.ps1` 或 `npm start` 启动。
- 没有与聊天、提醒或 life-core 的状态联动；形象固定 `aura`。
- Windows 11 把新托盘图标收进了溢出区，本轮未肉眼确认托盘图标本身，
  因此补了右键菜单作为退路。

## 6. 验收

环境：Windows 11 Pro for Workstations，2560×1440，16GB 内存，
RTX 3060 Laptop + Intel UHD，Node 22.22.0 / npm 10.9.4，
Electron 45.2.3，Vite 6.4.5，vgpu 0.3.1。

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 依赖安装 | `npm install` | 42 个包，27 秒；**首次未下载 Electron 二进制**（无 `dist/`、无 `path.txt`） |
| 修复二进制 | `node node_modules/electron/install.js` | PASS，得到 249,831,936 字节的 `electron.exe` |
| 构建 | `npm run build` | PASS，6.6 秒，`dist/assets/index-*.js` 697.37KB |
| 启动 | `npm run electron` | PASS，4 个 Electron 进程，渲染日志无错误 |
| 窗口验证 | PowerShell 截屏 + 模拟点击/右键 | PASS，见证据 |
| 启动脚本 | `scripts/start-pet.ps1` | PASS，单实例，未重复开窗 |
| 内存 | `Get-Process electron` | 4 进程合计 Working Set 412MB，Private 260MB |

失败与修复：唯一失败是 `npm install` 后 Electron 二进制缺失；手动执行
`install.js` 后恢复。未发现渲染、着色器或 IPC 错误。

Tauri 路径为 **BLOCKED**：缺 Windows SDK 且 `C:` 仅剩 2.8GB；已按用户选择改为 Electron，
不是 Tauri 构建失败后的静默降级。

## 8. 遗留风险

- **内存**：Private 260MB、Working Set 412MB，明显高于 Tauri 方案；不适合低内存机器。
- **托盘可见性**：Windows 11 默认把图标收进溢出区；若用户打开“鼠标穿透”，
  右键与球体都失效，只能从托盘溢出区关掉，存在把自己锁在外面的风险。
- **常驻 GPU**：30fps 的玻璃体持续绘制，本轮未测长时间 GPU 占用与电池影响。
- **启动方式**：无安装包、无自启；脚本依赖已存在的 `node_modules`。
- **上游维护**：murmur 未发布 npm，升级需要手工替换源码并重新验收。
- **未测试**：拖窗、位置恢复、穿透、GPU/WebGL2 后端选择、长时间稳定性。

## 9. 结论

**PASS（核心窗口）/ PARTIAL（日常使用）**：透明置顶宠物窗、点击反馈、右键菜单、
单实例与构建均已真实通过；安装包、开机自启、穿透、拖窗和位置恢复未验收。

当前可用于本机手工启动和视觉确认，不建议作为对外交付物。
下一步优先补：安装包或桌面快捷方式、开机自启、与聊天/提醒状态联动、
以及穿透模式的防锁死入口。
