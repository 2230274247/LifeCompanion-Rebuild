## 2. 目标与边界

在纯语义检索合同内做四项增强，不引入任何关键词/词面兜底：

1. **时间段解析**：识别「近N天/近N月/这周/本周/本月/上个月/上周/最近/最近几天」等窗口，作为结构化时间元数据约束候选，不参与内容相关度。
2. **结果去重**：索引层仍保留相同内容的每一条独立记忆（`prepare_user` 只编码一次、各来源各日期各保留独立行），但结果列表按内容哈希去重，避免同一事实按多时段重复淹没 top-8。
3. **交叉编码重排（两阶段）**：双塔余弦召回 → 取前 N 候选 → 交叉编码器 bge-reranker-base 重排 → 取 top-8。重排器离线加载、不可用时回退双塔排序。
4. **查询改写（LLM 前置，可配置）**：无指代时用 LLM 把抽象请求改写成自足的检索短语；紧超时、失败/超时/无 key 一律回退原查询，不阻塞召回。

所有改动只影响 life-core 的召回路径，不动 Silver-economy、不删数据库、不升级依赖、不暴露服务凭据。模型全部位于 H 盘仓库内 `services/life-core/data/embedding-models`，C 盘无模型权重（`~/.cache/huggingface` 仅 44K xet 传输日志）。

## 3. 架构实现与技术决策

### 时间段解析

新增 `_range(query, today)`：`近N天`（含中文数字一~十）、`近N月`（按日历月回退，不是固定30天）、`这周/本周`（周一起）、`本月`（月首起）、`上个月`（整月）、`上周`（整周）、`最近几天`（近3天）、`最近/近期/近来`（近14天）。返回闭区间 `(start, end)`，无窗口语言时返回 None。检测到窗口时把窗口短语从语义内容中剥离，候选过滤改为 `start <= _item_day(item) <= end`；单日期仍走原 `_day`，二者互斥且不冲突。

### 结果去重

打分排序后按 `_key(user_id, item)[2]`（canonical_text+value 的 sha256）去重，保留最高分（并列取最小 memory_id）代表，`meta["dedup_dropped"]` 记录丢弃数。索引层不受影响：`prepare_user` 仍按内容哈希分组只编码一次、但每个 memory_id/来源/日期各写一行向量。

### 两阶段重排

新增 `LocalReranker`（与 `LocalEmbedding` 平行）：固定 revision `Xenova/bge-reranker-base`（rev `280bcc27a84e0b898c251e06fddb25171bd9b101`），`specific_model_path` 指向 H 盘缓存、`local_files_only=True`、离线不下载。双塔通过阈值后取前 `memory_rerank_candidates`（默认32，最小8），用交叉编码器对（查询, 文档）打分，sigmoid 转置信度后重排，超出窗口的候选保持双塔顺序追加。重排器状态非 ready 时静默回退双塔。重排只改变排序、不改变纯语义性质。

### 查询改写

`_rewrite_query(settings, query, cache)`：仅在 `memory_query_rewrite_enabled`（默认 true）且无指代时调用；httpx 4 秒总超时、2 秒连接；返回 JSON `{"query": ...}`；空/失败/超时/无 key 一律返回原查询。512 条进程内缓存避免重复调用。`meta["query_rewritten"]` 记录是否改写。改写只作用于语义内容，日期/窗口元数据仍取自原查询。
