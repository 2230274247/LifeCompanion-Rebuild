## 3. 架构实现

- `memory_trace.py`：用户级、无原文的阶段诊断（enqueue/extraction/recall/delivery/publication），机器码 reason，脱敏，7 天清理。
- `embedding.py`：本地 fastembed `BAAI/bge-small-zh-v1.5`（512 维），后台预热，查询阶段不下载、不加载，缓存按用户/记忆/哈希/模型隔离。
- `retrieval.py`：授权优先于向量；关键词/实体/时间 + 向量混合召回；模糊指代用最近 4 条用户上下文或同会话 2 小时召回命中锚定；items（事件/计划，≤8）与 profile（稳定资料，≤4、≤1200 字）分离；总预算 6000 字符。
- `extraction_candidates.py`：多候选抽取（≤8），生日/职业/兴趣/目标/住址/饮品偏好与回避/关系，否定不反转，同一句多个事实分别保留，事件识别按完成语法而非旧词表否决；`use_llm` 单次 JSON 抽取并强制 evidence 落地。
- `main.py`：`process_event` 批处理包装 + `process_single_event`；同消息多候选逐条幂等入库；batch 完成后重放走快照不再重复调用抽取；Memos 发布失败可重试且不重复建事件；worker 循环中提醒/配置异常不再拖垮记忆抽取线程。
- 聊天端 `life.ts`：取消固定词门槛，每个非空 query 召回；收集同会话最近 4 条用户消息；`matched` 才注入证据；区分 401/403/网络/超时；telemetry 非阻塞；注入只改当前用户消息副本；服务不可达附有限状态说明。
- 网关 `server.mjs`：公开白名单新增 `memory-status`；内部 ingest/bootstrap 仍不外露。

## 5. 功能结果

- 链路可判断：`/api/v1/memory-status`、`/health` 的 `memory_pipeline`、内部 `/internal/v1/memory/telemetry`，区分 user_not_mapped / permission_denied / no_match / matched / excluded / injected / published 等。
- 自然召回：取消固定词门槛；关键词/实体/时间/向量混合；最近上下文补全“那个项目”指代；跨窗口、跨说法可召回（见验收脚本）。
- 保存：多事实（生日+饮品+职业）、否定（“不喜欢咖啡”不反转）、事件/计划区分、interest 列表键不冲突、当前纠正取代旧偏好。
- 分离：profile（受限常用资料）常驻注入，items（事件/计划）按相关性检索，图文影集继续独立筛选。
- 完成项均可通过自动化验证；真实容器替换、真实语义热模型、客户端全量类型检查未完成。
