# 回忆页日期崩溃修复 开发验收

## 1. 基础信息
- 任务：修复打开「我的回忆」页面即崩溃（前端 `RangeError: Invalid time value`）的问题。
- 日期：2026-11-12
- 版本/分支：主仓库 `feat/v03-collaboration-20261105`（HEAD `81738bd`）；前端在独立上游仓库 `products/librechat-custom`（分支 `lifecompanion-baseline`）。

## 2. 根因
后端对非 `day` 精度的记忆把 `occurred_at` 序列化为空字符串；前端 `new Date("")` 得到 Invalid Date，`Intl.DateTimeFormat.format` 抛 `RangeError: Invalid time value`，React 错误边界捕获后整页不可用。触发数据为 `/shared-memories` 共同回忆 `sources[0].occurred_at=""`。

## 3. 修复
前端对空日期做保护（不改后端契约）：
- `SharedMemoryCard.tsx`：`occurred_at || created_at` 回退。
- `Memories.tsx` `groupMemories()`：无日期归入 `undated` 组，显示「日期不详」。
- `MemoryCard.tsx` / `MemoryDetail.tsx`：空日期显示「日期不详」。
- `en/translation.json`：新增 `com_life_undated`。

另：主仓库 `scripts/start-lifecompanion.ps1` 改为每次启动都替换 8010 上的 life-core（原逻辑在健康时跳过，会把 `H:\LifeCompanion-v1-runtime` 的残留旧实例误判为「已在运行」，导致旧代码继续跑）。

## 4. 验证
- 前端：`npm run build`（vite，52s）成功；`docker restart lifecompanion-librechat`。
- 浏览器打开 `/memories`（管理员账号）：正常渲染，控制台 0 错误；`/memories` 与 `/shared-memories` 均 200；共同回忆时间显示「11月6日 10:52」；5 段无日期回忆归入「日期不详」组。
- 启动器：PowerShell `ParseFile` 语法检查通过。

## 5. 结论
PASS。回忆页不再崩溃，空日期优雅降级。
