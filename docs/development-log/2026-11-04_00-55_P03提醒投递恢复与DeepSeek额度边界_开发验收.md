3. 验证通知首次失败持久化退避、独立 scheduler 重启后重试、无重复投递。
4. 检查浏览器 Chip 的键盘、触摸、取消、刷新和独立登录恢复。
5. 记录当前 DeepSeek 配置的真实成本与剩余 P02/P03 缺口。

修改旧 Silver、部署常驻 scheduler、推送 Git、把 Mock 当产品 E2E。

## 3. 架构与实现

- `ReminderService` 在一次 reconciliation 内只遍历已授权 owner 一次。
- Vikunja notification 在计划时刻前后 60 秒接受；真实延迟恢复不再漏掉。
- outbox 的 `next_attempt_at` 早于计划时刻时被推迟，提前送达不提前通知。
- 发送前以 owner/task/current scheduled_at 重算 event_id；改期旧事件直接 suppressed。
- 内容使用当前权威提醒标题；任务被改期后旧 payload 不能覆盖新值。
- `reminder_scheduler_runs` 持久记录每次开始/完成、用户数、接收数和错误码。
- 每轮最多发送 100 条，剩余 pending 留给下一轮，避免无限内循环。
- `LIFE_REMINDER_SCHEDULER_EXTERNAL=true` 时 Core 内嵌恢复/发送停止，由独立 scheduler 执行。
- 默认 false 保持兼容；验收明确没有把进程退出后宣称常驻服务存在。

既有 Vikunja、ntfy、LangGraph SqliteSaver 和 APScheduler 3.x 继续复用。
依赖：APScheduler 3.11.3、SQLAlchemy 2.0.55、LangGraph 1.2.19、
langgraph-checkpoint-sqlite 3.1.3，安装元数据均标记 MIT。
