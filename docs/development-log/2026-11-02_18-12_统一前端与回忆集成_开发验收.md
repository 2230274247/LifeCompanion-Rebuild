## B. 目标与范围

原先入口、LibreChat 和 Memos 各有页面。聊天虽能进入 Memos，回忆列表 API 只返回
life-core 索引，没有读取实际 Memo，也没有统一详情、筛选和同页导航。

本次完成目标：

1. 使用 LibreChat 现有 React 路由、Root、Provider 和侧栏形成一个 SPA，以真实聊天回归检查。
2. 通过 life-core 官方 API 适配读取私有 Memos，检查权限、分页、筛选、详情与失败状态。
3. 保留服务端消息持久化后的接入，使用真实聊天、Memos 和同来源重试验证链路。
4. 保留现有品牌，检查五种视口和手机侧栏，归档真实截图。
5. 建立永久独立开发日志、索引及上游完整补丁。

排除：重写聊天引擎、合并数据库、自动语义事件归并、多用户自助开户、
第三方身份平台、长期记忆召回、生图、提醒调度/推送、Android APK、公网部署。
这些功能不展示为已交付。

审计与计划见 `docs/V02_IMPLEMENTATION.md`。读取了 README、架构、运行手册、
阻塞项、历史演示准备验收、上游差异/版本、Compose、设计 Token 和 LibreChat AGENTS。
采用已有组件、React Query、data-provider 契约和版本化语义主题；
按 vercel-react-best-practices 检查数据读取并发和重复请求，未引入新依赖。

## C. 架构与实现

```text
浏览器 127.0.0.1:3001
  └─ product-portal Node 流式网关
      ├─ /c/*、静态资源、/api/* → LibreChat :3080
      │    └─ 原 React Root / Provider / 聊天 / 统一导航
      └─ /life-api/api/v1/me、memories → life-core :8010
           └─ JWT + 显式映射 + 事件归属 → Memos :5230 官方 API

聊天保存成功 → 原 BaseClient 服务端钩子 → 内部 ingest
  → 来源过滤 / 同意状态 / 用户作用域幂等 → Memos 私有 Memo
  → 统一回忆页读取
```

### 前端与部署

- 保留 `/c/new`、`/c/:conversationId` 以及原始聊天内核。
  增加 `/memories`、`/memories/:memoryId`，无新标签、iframe 或 Memos 原生 UI 跳转。
- 共用页头、导航、侧栏和版本化 Life 主题，沿用纸张、墨绿、银杏黄。
  品牌来自既有 Token 和 SVG，不另建视觉系统。
- 切换回聊天使用按用户记录的最近会话路径；聊天草稿复用原机制。
  回忆筛选保存在 URL；列表滚动按用户和筛选保存在 sessionStorage。
- 列表显示发生时间、标题、摘要、类别、来源、标签；详情读取真实 Memo 原文，
  原始 Markdown 以文本展示，避免未经处理的 HTML。来源会话仍由 LibreChat 授权。
- 网关透传 SSE 字节；回忆入口只允许 GET 的公开契约，内部 ingest/bootstrap 无法经该入口访问。
  不向 life-core 透传 Cookie，不注入服务端密钥，剥离浏览器传入的内部令牌。
- Compose 新增独立 overlay，将本机构建 dist 只读挂载到现有 LibreChat。
  Express 缓存入口 HTML，构建成功后只重启 LibreChat；不清理数据库。

### API、数据模型与认证

| API | 契约与边界 |
| --- | --- |
| `GET /api/v1/me` | Bearer access JWT，返回显式映射的用户信息 |
| `GET /api/v1/memories` | 原 `memories` 保留，增加 `page`、`page_size`、`total`、`has_more` |
| 查询参数 | `q` 搜索索引标题/摘要；`on_date` 按香港日期；`order=asc/desc`；页大小最多 50 |
| `GET /api/v1/memories/{event_id}` | 先查当前用户所属已发布事件，再读 Memo；未授权/不存在不泄露他人内容 |
| `POST /internal/v1/events/ingest` | 原内部令牌接口保留，未暴露给浏览器 |

没有 schema 迁移。回忆仅包含 life-core 已发布的索引事件；直接在 Memos 新建且没有
该索引的记录不会出现在列表。搜索不是 Memos 全文搜索。

- life-core 校验 HS256 签名、真实 id、到期及畸形 JWT，移除 refresh Cookie 回退。
  浏览器复用 LibreChat 当前访问令牌及原刷新机制，普通用户只登录一次。
- Memo 读取核对资源名、creator、PRIVATE 与 NORMAL；错误返回脱敏 502，
  不用空数据伪装失败。每页最多 6 路并行读取。
- 发布前先读取 Memos `/api/auth/me`，确认 PAT 账号等于映射用户，再写入；
  PAT、DeepSeek Key 和内部令牌均只在服务端。
- 原全局 `source_type:message_id` 键可能串用户，本次新事件键加入 life user；
  旧事件不改写，通过原 ingest_attempts 映射兼容读取/重试。
- Memos 网络失败记录 failed 事件和任务，保留安全错误码，之后同来源可重试。
  同来源使用稳定事件/Memo；不同消息语义相同的事件尚不自动归并。
- 当前仅明确映射单用户；不能宣称多用户开通验收通过。
  退出会清除浏览器登录状态，但 life-core 没有访问 JWT 即时撤销列表，
  已签发有效访问令牌可能继续可用到期。

## H. 遗留风险与下一步

- 上线前阻塞：真实多账号映射/开户/隔离端到端验收，访问 JWT 即时撤销策略，

- 当前分页先取当前用户事件索引后内存筛选；每页读 Memos 有界并发，但没有大数据量压测，
  不对长期大量回忆的延迟/内存作承诺。构建提示部分 chunk 大于 1500 kB。
- 搜索仅索引标题/摘要；Memos 无索引记录不显示；不同消息语义归并未实现。

  真机键盘、深色/高对比/reduced-motion 的完整视觉测试仍需补充。

- 生图供应商、提醒推送和 Android APK 仍未交付；详见 `docs/BLOCKERS.md`。
- 没有执行全项目安全审计、依赖漏洞审计或完整测试全集。
