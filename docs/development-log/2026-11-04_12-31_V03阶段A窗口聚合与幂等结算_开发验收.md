## 2. 目标与边界

### 2.1 目标

- 实现 `00:00-11:00 / 11:00-16:00 / 16:00-24:00` 三时段，晚间归属于同一业务日并在
  次日 `00:05` 结算；数据库只保存 UTC，业务日期和展示按用户 IANA 时区计算。
- 时区或时段策略变更在稳定边界生效，持续使用持久 cursor，不重复、不遗漏跨日区间。
- 同一事件的多次叙述合并为一个候选，保留全部原始消息 ID 与原文；同日独立相似事件不误合并。
- 复用 P04 八维评分、精确来源校验、持久调用账本和额度门，不新建第二套评分系统。
- 以 `(user_id, local_date, slot)` 唯一约束确保同一业务日同一时段最多一条结算记录。
- 评分领取、租约、成功结果缓存、异常结果、重启恢复和迟到证据都要幂等可审计。
- 每个候选在 `review_json` 中保留选中/未选中/排除结果、理由码、八维分数及原始来源证据。

### 2.2 明确排除

- 不进入阶段 B/C/D，不实现 Kolors、私有图片文件、图文页面或稀有卡。
- 不调用任何真实生图 API；`LIFE_MOMENT_IMAGE_GENERATION_ENABLED=false`，图像 Worker
  在本阶段验收中返回“未改数据”。
- 不修改真实用户数据库、不重放原用户聊天、不删除旧回忆、不执行生产迁移。
- 不合并分支、不推送 Git、不恢复 P05、不部署公网。
- 不把 Mock 评分或单一真实评分样例外推为完整语义准确率或最终 V0.3 DoD。

## 3. 架构实现

### 3.1 时间窗口与跨日

新增 `app/moment_windows.py`：

- 默认边界为 `11:00 / 16:00 / 24:00`，以用户时区的墙钟时间构造，再转 UTC 持久化。
- 晚间窗口为业务日 `16:00` 至次日 `00:00`；`settle_after_utc` 独立保存为结束时间后 5 分钟。
- `next_window_after()` 只用持久 cursor 和历史业务键推进；策略切换后从同一 UTC cursor 继续。
- `next_policy_boundary()` 找到当前策略下首个未结束边界，时区变更在此边界生效，避免新策略
  追溯改写已结算窗口。
- 半开区间 `[start, end)` 防止边界消息重复；测试覆盖非整数偏移和 DST 的缺失/重复墙钟时间。

### 3.2 同事件语义聚合

新增 `app/moment_semantics.py`：

- 提取动作、时段、地点、距离、重复提示和指示性复述词，仅在同日且存在足够锚点时合并。
- 明确出现“第二次”、不同明确时段、不同编号地点、“另一座”等独立发生提示时不合并。
- 相同文本/相同地点/距离但发生时间相距过远时不合并；组内按完整相容关系贪心聚类，
  不由 A-B、B-C 的桥接关系传递合并并不直接相容的 A-C。
- `merge_group()` 保留组内全部 memory ID、revision、message ID 和逐字原话；不会修改或生成聊天原文。
- 候选向 P04 传递 `same_occurrence_retellings`，明确告诉评分器多个来源是同一事件的复述证据，
  而不是重复事件；单条足够明确的原话也不因“只出现一次”被压低 source sufficiency。

### 3.3 P04 评分复用与可审查记录

扩展 `app/recollection_scoring.py`，复用既有八维权重、JSON schema、消息 ID/原话校验和请求账本：

- 候选仍必须返回系统提供的每个 memory ID，引用只能来自该候选的来源消息。
- 新增同事件复述上下文，修复真实评分首次把三条跑步复述误判为 `DUPLICATE_EVENT` 的问题。
- `moments.review_json` 保存窗口、策略、阈值、评分模式、候选原文、完整来源、维度和理由。
- 结果码区分 `SELECTED / NOT_SELECTED / EXCLUDED / PENDING_SCORE / CANCELLED`，
  同时保存 `HIGHEST_ELIGIBLE_RANK`、`LOWER_RANK`、`LOW_PERSONAL_MEANING` 等原因。

示例审查结果可回答：

- 为什么选中某事件：最终候选理由 `HIGHEST_ELIGIBLE_RANK` 和八维分数高于其他合格候选。
- 哪些聊天支持：候选 `sources` 中的 message ID 与逐字 quote。
- 为什么其他事件没有入选：低于阈值、隐私/证据不足、与选中项并列但排名较低等明确原因码。

### 3.4 持久结算、幂等与恢复

扩展 `app/moments.py`：

- 为旧 `moments` 增量增加 11 列，不重建表：
  `local_date`、`settle_after_utc`、`policy_version`、`policy_config`、
  `policy_effective_utc`、`coverage_note`、`score_claim_id`、`score_lease_until`、
  `review_json`、`reviewed_late_memory_ids`、`late_checked_at`。
- 新增 `moment_schedule_state`、`moment_policy_history`、`moment_migration_conflicts`、
  `schema_migrations`；候选表增加组成员和来源 revision。
- 建立部分唯一索引 `(user_id, local_date, slot) WHERE local_date IS NOT NULL`；
  存量冲突只进入冲突报告，不删除数据、不强行创建会失败的索引。
- 评分用 SQLite 立即事务和 claim/lease 领取；崩溃后先查持久调用账本。
  已有成功结构化结果只做本地最终化，不二次请求；未知结果保持阻断，不自动重试扣费。
- 迟到证据按 `late_checked_at` 轮转扫描，避免老窗口永久占满扫描批次；同事件迟到复述追加
  原始来源，不同事件记 `ARRIVED_AFTER_SETTLEMENT`，不伪装成已评分候选。
- P03 APScheduler 注册 `moment-settlement-intent`，callback 只写持久意图；
  不把模型或图像耗时放在 scheduler 线程内。

### 3.5 授权、兼容和配置

- V0.3 文字回忆只要求记忆授权；图片外发仍硬校验 `image_consent`，关闭图片授权不阻断文字结算。
- 关闭图片授权会清空已存图片 BLOB/MIME，但保留文字、来源和审查记录。
- 旧 `23:00` 配置只迁移为 `24:00` 收口，保留权限审计与策略历史；不读取或重写真实用户数据。
- 新增配置：V0.3 开关、扫描上限、评分租约、外部调度标记、图像 Worker 硬开关。
- 默认配置继续保持 V0.3 关闭和生图关闭，只有独立验收库显式启用。

**阶段 A 真实语义验收：PARTIAL。**

- 当前只有一个真实合成场景，未形成多场景人工准确率、误合并率或误排除率。

**总体状态：PARTIAL，不建议直接进入阶段 B。** 建议先由用户确认该样例的真实 ground truth
