4. 用 Mock 测试验证响应解析、完整解码和预算拦截，再执行真实模式。
5. 固化脱敏证据、验收日志和兼容现有 FastAPI/Moments/Worker 的设计。

## 3. 架构实现

### 3.1 官方合同

官方生图端点为 `POST https://api.siliconflow.cn/v1/images/generations`。
Kolors 请求使用 `model`、`prompt`、`image_size`、`seed`、
`num_inference_steps` 和 `guidance_scale`；文档未列出通用 `batch_size`。
成功响应为：

```json
{
  "images": [{"url": "string"}],
  "timings": {"inference": 0.1},
  "seed": 0
}
```

响应头 `x-siliconcloud-trace-id` 是平台追踪标识；图片 URL 仅一小时有效。
文档列出的错误码为 `400/401/403/404/429/503/504`，其中 `400` 示例 code
为 `20012`，`503` 示例 code 为 `50505`。完整核对见
`evidence/v03-b0-kolors/official-api-contract.md`。

### 3.2 独立实现

- `provider.py`：实现最小 `ImageProvider` 协议、Kolors 适配、单图约束、
  HTTPS 公网 URL/DNS 检查、禁止跳转、20 MB 上限、完整 Pillow 解码、
  尺寸/格式/MIME/SHA-256/非空白技术检查。
- `verify_kolors.py`：只读取独立 `SILICONFLOW_API_KEY`；真实调用前动态
  核对官方免费价格、账户模型可见性和 ¥0 硬预算；请求前原子写一次性账本。
- `test_provider.py`：使用 `httpx.MockTransport` 和内存 PNG，不访问真实
  Provider；覆盖成功下载/完整解码、多图拒绝、价格/权限门禁和二次请求拒绝。
- 输出目录 `evidence/runtime/v03-b0-kolors/`：保存脱敏请求、响应标识、
  错误日志和最终校验；不在静态站点、日志或前端暴露 Key/签名 URL。

### 3.3 业务接入设计

新增 `docs/architecture/V03_B0_KOLORS_PROVIDER.md`，设计为：

- Provider 注入现有 `Moments`，不接管用户同意、SQLite、FastAPI 路由或 Worker；
- 保留 `main.py` 的现有 `moment-generation` 线程和 `Moments.run_one()`；
- 生产接入时只从独立 `IMAGE_PROVIDER_API_KEY` 读取凭据，不回退聊天 Key；
- 超时/不确定 5xx 保持 `unknown`，不自动重复扣费；原始 URL 不下发前端。

本任务没有把该参考实现导入 `services/life-core`，也没有启动真实用户任务。

- P1：价格、模型可用性和返回域名可能变化；每次真实运行必须重新过门禁。
- P1：真实 timeout/5xx 仍可能产生“供应商已接收但结果未知”；一次性账本
  会阻止脚本自动重试，但无法提供外部 exactly-once 保证。
- P1：技术指标不能证明语义一致性、审美质量或人物/场景事实正确；
  真实图片成功时仍需人工检查。
- 未接入生产：没有媒体私有读取、越权拒绝、缩略图、审核和分步发布证据。
