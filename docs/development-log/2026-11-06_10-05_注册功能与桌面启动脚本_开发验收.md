## 需求

1. 普通用户可通过「用户名（必填）+ 昵称（可选）+ 邮箱（可选）+ 密码」自助注册，注册后自动登录。
2. 登录支持「用户名或邮箱」。
3. 自注册用户永远是普通 `USER`，不得把首位注册者引导为 `ADMIN`。
4. 用户名唯一、重复用户名与两次密码不一致要有清晰错误。
5. 日志与错误不得泄露密码。
6. 桌面一键启动脚本打印项目信息、识别端口占用进程、只复用可证明归属的服务、前端过期时重建、健康检查全部通过后才打开浏览器、日志不带密钥。

## 运行验证（真实链路）

LibreChat 运行在 Docker `lifecompanion-librechat`，前端为本地重建后的 `client/dist`。

- 用户名注册：`POST /api/auth/register`（用户名 + 密码 + 确认密码）返回 `200`，`role=USER`，占位邮箱 `...@users.invalid`，返回 `token` 与脱敏 `user`，`emailVerified=true` 且无 `expiresAt`。
- 用户名登录：`POST /api/auth/login` 使用用户名返回 `200` 与 `token/user`。
- 重复用户名：返回 `409 {"message":"Username is already in use."}`。
- 普通用户访问管理接口：`GET /api/admin/users` 返回 `403 Forbidden`。
- 桌面启动器（`-NoBrowser`，服务已在运行）：打印项目信息 → Docker/提醒容器复用 → 前端 dist 判定为最新 → life-core/网关身份识别并复用 → 四个健康检查通过 → 完成，全程未打开浏览器、未误杀进程。
- 桌面启动器（`-SkipBuild`，前端源码过期）：正确在重建阶段报「前端源码已过期…未重建」并停止。
- 数据备份：`infra/runtime/backup/20261106-username-index/`（Mongo 归档 `librechat.archive` + `life-core.sqlite3`）。
- 用户名唯一索引：`users` 集合创建 `{username:1, tenantId:1}` 部分唯一索引成功，创建前确认无重复/空用户名。

## 残余风险

- 前端重建耗时较长（约 1–2 分钟）；首次冷启动且源码过期时会自动重建，双击体验会有等待。
- 端口归属判断依赖进程命令行特征（`uvicorn app.main:app --port 8010`、`node server.mjs`）。若其他程序用完全相同的命令行伪装，仍无法区分，但已改为「无法证明归属即停止」，不做进程名误杀。
- 邮箱可选但后端仍会为无邮箱账号生成内部占位邮箱；该占位邮箱不会展示给用户。
- 浏览器端完整注册→聊天→回忆/提醒的自动化 E2E 未纳入本轮（已做真实 API 注册/登录与截图，但回忆/提醒需走 life-core 引导，未在本轮重跑）。
- 真实邮箱验证流程（`emailEnabled=true`）依赖 SMTP，未在本机验证；当前部署 `emailEnabled=false`。
