## 2. 目标与边界

### 原问题

1. 普通生活分享被模型扩写成第一人称散文，并编造用户没有说过的人物、动作、地点和心理活动。
2. `/memories` 首屏先显示生成任务，真正的已发布回忆只是单列文字，没有图片、日期分组和影集体验。
3. 后台图片生成完成后与已发布事件没有读取关联，用户下次进入影集看不到新图。

### 本轮目标

- 普通聊天与后台 Memory Extraction / Image Generation Job 职责分离。
- 打开“我的回忆”直接显示已发布图文回忆，而不是任务队列。
- 支持日期分组、搜索、日期筛选、排序、详情、图片放大与移动端单列。
- 生成图自动关联事件并在下次读取时静默出现；失败可重试。
- 复用现有组件和已安装的成熟交互库。

### 明确排除

- 不把 React 18 + LibreChat 重写为 Vue 3。
- 不覆盖现有 Ember 视觉 Token、品牌、侧栏和主题注册表。
- 不修改真实原始数据，不批量回填历史聊天或图片。
- 不执行真实付费批量模型/生图调用。
- 不 Push、不部署公网、不执行破坏性数据库操作。
- 不把合成图片、AI 图片或 Mock API 冒充真实用户照片。

## 3. 架构实现

### 3.1 技术栈映射

设计包假设 Vue 3，但仓库实际统一入口为 `products/librechat-custom` 下的 React 18 + LibreChat，
后端为 `services/life-core` FastAPI。按用户要求不重做技术栈，采用：

- Motion for Vue → 已安装的 `framer-motion`。
- Radix Vue / Reka UI → 已安装的 `@radix-ui/react-dialog`。
- PhotoSwipe → 当前单图契约复用 Radix Dialog；未新增第二套图片查看器。
- 视觉颜色、字体、Button、主题和现有导航保持不变。

### 3.2 聊天边界

- `librechat.yaml` 两个拾光模型规范加入同一版本化 `promptPrefix`。
- Prompt 源文件为 `life-companion-chat.v1.md`，YAML 内容由质量门禁校验一致性。
- 明确允许用户主动要求文学创作，但创作不得回流成“真实经历”。
- 后台摘要、生图、提醒不进入普通聊天输出通道；聊天不得无回执声称已完成任务。

### 3.3 图文影集

- 列表接口新增向后兼容的 `has_image` 和 `media` 字段。
- 列表只返回缩略图，详情才返回大图，避免首屏传输全部原图。
- `Memories` 移除首屏 `MomentList`，按时间顺序分组卡片。
- `MemoryCard` 负责图文卡片、AI 声明、无图/失败降级和 Motion 入场。
- `MemoryDetail` 负责大图、事实文字、来源对话、权限入口和 AI 声明。
- `MemoryImageDialog` 负责单图放大、Esc、关闭和焦点恢复。
- 搜索、日期、排序和页码保留在 URL；返回详情时恢复原筛选状态。

### 3.4 自动发布与媒体关联

- `moments` additive migration 增加 `thumbnail`、`thumbnail_mime`、`image_width`、`image_height`。
- Provider 成功后验证图片可解码，生成 JPEG 缩略图和宽高。
- 生成成功调用现有 `publish_event`，成功后标记 `published`。
- Memos 失败时保留图片并标记 `MEMOS_PUBLISH_FAILED`，后台 worker 可重试。
- `media_for_event()` 通过 active memory → event 关联最近有效生成图。
- 相同窗口/候选使用现有幂等键；不重复生成同一事件。

### 3.5 数据与权限

- 不修改 `events` 历史字段，不删除旧图片，不回填历史生成图。
- 回忆列表只来自当前映射账户的 `published` 生活事件。
- 媒体查询同时校验 owner、memory state、event id 和 moment 状态。
- 真实数据库未参与本轮演示数据写入。

## 5. 功能结果

### 已完成

- 普通聊天拥有明确的事实边界和自然回复目标。
- 影集首屏直接显示日期分组图文卡片，不再先显示生成任务。
- 搜索、日期筛选、排序、分页和详情返回状态可用。
- 无图、破图和搜索空态不伪造内容。
- 桌面/平板/手机响应式通过。
- 生成图自动关联已发布回忆并在读取时出现。
- Memos 发布失败可重试，不回滚已生成图片。

### 未完成 / 未验证

- 真实付费模型 50 条回答质量回归。
- 真实付费生图时段链路和预算核验。
- 真实用户照片、多图、EXIF、超大文件。
- Safari / Firefox / 真机性能与弱网。

### 既有功能影响

- 保留 `/memory-settings`、生成管理页和既有主题。
- `MomentList` 不再占据“我的回忆”首屏，但相关设置/管理能力仍保留。
- 旧 API 调用方不传图片字段时仍可正常读取。

### 失败与修复

1. 测试夹具的 `memory.media` 在 TypeScript 严格模式下可能为空。
   - 修复：测试断言改为可选访问 `memory.media?.thumbnail_data`。
   - 复测：typecheck PASS。
2. 合成种子脚本误读 `accounts.json` 的旧 `id` 字段。
   - 修复：按实际 `memos_user_id` 查询隔离用户映射，并加强缺失检查。
   - 复测：种子 PASS，未写入真实库。
3. Playwright 包期待 Chromium 1234，本机缓存为 1248。
   - 处理：脚本自动复用本机已安装 headless shell，不下载新浏览器。
4. Jest 完成后进程不退出。
   - 处理：记录 PASS 后安全终止进程；该问题为既有运行器行为。
5. 用户打开 `127.0.0.1:3001/memories` 仍看到旧“时段回忆”。
   - 根因一：LibreChat 容器在启动时缓存了旧 `index.html`，虽然磁盘已构建新资源。
   - 根因二：`life-core:8010` 是构建前启动的旧进程，旧 API 不返回 `media`。
   - 处理：重启本机 LibreChat 容器与 life-core；未删除容器数据或数据库。
   - 复测：3001 返回 `index.DpFbGB3f.js` / `index.DYZb0iVj.css`；管理员影集页
     3 张卡片中 2 张显示图片、1 张显示无图降级，旧任务标题不存在，横向溢出为 0。
