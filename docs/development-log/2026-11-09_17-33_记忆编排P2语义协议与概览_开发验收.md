## 2. 目标与边界

让「普通问答 / 主题记忆 / 事件概览 / 提醒查询 / 提醒准备 / 联网 / 澄清」由模型输出严格结构化任务来路由，后端只校验和受控执行，不靠关键词猜意图。事件概览按授权事件的发生时间窗口查询并分页，不再经过内容相似度阈值，从而支持「近期最有意思的一件事」这类模糊复杂回顾。

## 3. 架构与技术决策

- 新增 `app/assistant_plan.py`：`TimeWindow`（绝对起止日或 `relative_days`，禁止冲突/倒置/空窗口）、`AssistantTask`（`action` 白名单 Literal，`query`/`expansions` 为检索假设、上限 2 条，`reminder` 仅 `prepare_reminder` 可带，`clarify` 必须带澄清文本）、`AssistantPlan`（`version="1"`，任务 1–4，每轮最多一个 `prepare_reminder`）。
- `SemanticPlanner.plan` 仅在配置 `memory_llm_key` 时请求模型，temperature=0、`response_format=json_object`、`max_tokens=1200`；任何 provider/解析异常统一转为 `PlanUnavailable`，不把模型输出当可执行权限，也不冒充「没有记录」。SYSTEM 明确只输出 JSON、任务白名单、窗口用给定当前日期/时区计算、禁止 user_id/权限/SQL/URL/成功状态。
- `MemoryRetriever.overview`：按 `_item_day` 取事件/计划发生日，窗口内事件按发生日排序分页；未标注发生日的来源原话单独归入 `undated_count`，不伪造日期也不混入时间轴。覆盖元数据含 `start/end/returned/total_count/truncated/has_more/undated_count`。
- `/internal/v1/assistant/plan` 与 `/internal/v1/assistant/execute`：内部令牌门禁 + 用户映射 + `recall_consent` 权限门禁；`execute` 逐任务受控执行（`search_memory`→`retrieve`、`overview`→`overview`、`query_reminders`→真实提醒列表、`prepare_reminder`→`needs_draft`、`web_search`→`unavailable`、`clarify`→澄清文本），证据项含 `occurrence_day` 且仅在能解析到发生日时给出。

## 5. 功能结果

`/assistant/plan` 返回 `planned`（含任务）/`user_not_mapped`/`permission_denied`/`planner_unavailable` 四态，模型输出经 Pydantic 严格校验。`/assistant/execute` 逐任务执行并返回 `results`，概览按时间窗口列出事件、分页标记 `has_more`，未标注发生日的内容不进事件时间轴；`web_search` 不冒称已执行，`prepare_reminder` 只返回草稿字段。
