## 目标与边界

证明提醒链路的“真实动作”闭环：创建提醒后，真实上游 Vikunja 生成任务并按计划触发，回调进入本机 life-core，再由 life-core 把通知投递到真实 ntfy topic，最后本地状态从 `scheduled` 变为 `due`（已触发）。

隔离性：复用隔离合成账号 spa-a（`vikunja_user_id==2`）与其独立 ntfy topic；但本测试每次都**新铸**一个 7 天短期 scoped Vikunja API token（旧 token id=4 已于 2026-11-09 过期），并注册指向 8011 的**独立** webhook，绝不改写产品基线 `users.json`、也不触碰主 life-core（8010）的既有 webhook（id=11）。每次用全新 sqlite。

不改动真实业务数据、不打印/提交任何秘密；凭据只读自 gitignored 运行目录。

## 关键结论（为何旧脚本会失败，如何修）

| 环节 | 说明 |
| --- | --- |
| 旧 token 过期 | `users.json` 里的 spa-a `api_token`（token id=4）已过期，Vikunja 返回 401。改为用 spa-a 登录名密码 `POST /api/v1/login` 后 `POST /api/v2/tokens` 新铸 scoped token |
| webhook 权限 | scoped api_token 只有 `tasks`/`notifications` 权限，无权管理 webhook；webhook 注册须用登录 JWT。且创建端点：`POST /api/v2/user/settings/webhooks` 或 `PUT /api/v1/user/settings/webhooks` |
| `delivery_channel` 枚举 | `ReminderRequest.delivery_channel` 为 `Literal["push"]`，传 `ntfy` 会被 422 拒绝 |
| 公开 API 隐藏 task id | `public_reminder` 会剥离 `upstream_task_id`；改按标题在 `GET /projects/{id}/tasks` 中定位真实任务 |
| 本地状态语义 | `mark_reminder_fired` 把状态置为 `due`（不是 fired/completed）；验收按 `due`/`completed` 判定 |
