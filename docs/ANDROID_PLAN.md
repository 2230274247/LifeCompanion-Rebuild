# Android Plan

本周目标是桌面浏览器真实纵向切片。Android 只完成技术边界和路线规划，
不宣称已有可安装 APK。

## 可复用部分

- `life-core` 的业务 HTTP API：身份、事件、回忆索引、提醒和未来图片任务。
- 用户与授权模型：LibreChat 用户、`life_user_id`、Memos 用户映射。
- DeepSeek 等服务端模型调用。
- Memos 私有回忆作为跨端共享的时间轴数据源。

## 不可直接复用或必须单独验证

- 浏览器 Cookie、LibreChat 前端私有存储和页面路由。
- 麦克风、相册、文件和通知权限。
- Android 后台任务、离线缓存、弱网恢复和深链接。
- APK 签名、升级、分发和安全存储。
- 把两个完整 Web 应用直接塞进一个 WebView 的交互与认证体验。

## 方案比较

| 方案 | 优点 | 风险 / 成本 | 当前结论 |
| --- | --- | --- | --- |
| Capacitor 封装自有顶层前端 | 可复用未来自有 React/HTML 前端；上线路径较快 | 仍需处理 Cookie/JWT、CORS、通知、权限、WebView 兼容；不能直接封装两个完整上游网站后宣称完成 | 优先 PoC 候选 |
| Flutter / 原生 Android | 对通知、语音、离线与系统集成最可控 | 需要重建聊天、回忆和设置 UI；成本最高 | 多端体验稳定后考虑 |
| 仅 PWA / 浏览器 | 成本最低 | 不是 APK，不能替代 Android 安装、后台和通知验收 | 只能作为过渡 |

## 推荐演进

1. 保持自有业务 API 和身份边界稳定。
2. 新建轻量移动客户端 UI，聊天可调用 LibreChat 受支持 API，或由 `life-core`
   提供统一代理，但不得依赖浏览器私有会话。
3. 用 Capacitor 做最小 PoC，只验证登录、会话列表、发送、回忆列表、设置和
   深链接。
4. 单独打通 Android 通知与提醒执行；把“任务已入队”和“通知已送达”分开记录。
5. 增加语音输入、相册、离线队列、重试和撤销授权。
6. 真机验收必须保存设备型号、Android 版本、权限状态、弱网/离线测试和录屏。

## 后续验收清单

- 真机安装 APK
- 登录并安全保存短期凭据
- 聊天、历史回看和会话切换
- 查看私有回忆及图片
- 语音输入权限与录音状态
- 提醒创建、后台触发和通知状态
- 离线/恢复/重复请求幂等
- 数据删除与授权撤回

上述项目均不属于 2026-11-04 桌面 P0 的已交付范围。
