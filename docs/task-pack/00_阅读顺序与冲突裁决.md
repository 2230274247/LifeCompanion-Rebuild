# LifeCompanion-Rebuild｜开发任务包使用说明

**生成日期**：2026-11-03  
**唯一允许修改的产品主项目**：`H:\AI For research institute\LifeCompanion-Rebuild`  
**适用对象**：Codex / Claude Code / 开发与验收负责人  
**状态**：设计与执行指令包；**不是代码审计结果，不代表已执行克隆或修改主项目。**

## 1. 正确的执行顺序

1. 先让 Codex 读取 `01_全项目回顾_现状_问题根因假设与差距.md`，建立产品目标。
2. **必须先执行 `P00_项目身份锁定_架构审计_选择性移植.md`**。没有 Rebuild 根路径、运行服务和数据库身份的核验，不可写入任何项目。
3. 逐一发送 `P01` → `P07`。每一阶段要求实际修改、实际运行、生成阶段独立日志、逐项记录证据、做回归，再进入下一阶段。
4. `10_Codex总控目标提示词.md` 可在所有阶段文件一同放入 Codex 工作上下文后作为常驻目标指令；它**不授权跨阶段修改生产数据**。
5. `11_跨阶段总验收矩阵.md` 是项目最终检查表。不能用单元测试数量取代产品端到端验收。

## 2. 同一需求冲突时，严格按以下优先级

1. 用户在本轮确定的产品主项目、完整目标与隐私/安全边界。
2. Rebuild **实际仓库**已生效的安全、数据、设计和运行约束（先审计）。
3. `LifeCompanion-Rebuild_...V2.0.md`：唯一写入目标、云端模型、不要求新向量、旧成果选择性移植。
4. `时光有声_V0.2.3_...专项整改提示词.md`：少表单、快捷时间、跨会话、详情跳转、三段回忆的产品验收。
5. `时光有声_V0.2_...云端API版_V1.1.md`：可借鉴主库/证据/Graphiti/调度设计；但其旧项目路径、强制新供应商内容被本次覆盖。
6. `时光有声_V0.2_...V1.0.md`：仅作设计演变史；**本地 Qwen、Laya、Embedding 部署要求全部废止**。

**特别裁决**：已有 Memos/LibreChat/Vikunja/ntfy/life-core 优先复用；不为了“开源强制集成”再造功能相同的第二套业务主库或页面。Graphiti 在无有效 Embedding Provider 时，完整原生功能保留 `BLOCKED_EMBEDDING`，其余图查询与记忆业务独立完成。

**提醒交互裁决**：用户**明确请求**提醒且必要字段已完整、本人已通过明确交互完成授权时，可以直接经服务端创建并显示回执；仅缺时间时，用点击快捷选项一次补齐，不再重复弹全量表单。用户**只是提到未来日程**时，仅给不打扰的建议，不可擅自创建任务。改期、取消需要可靠定位目标并按现有授权规则确认。

## 4. 交付纪律

每个阶段须在 Rebuild 文档体系内**新增一份独立开发日志**（不得覆盖上阶段日志），包括：目标、开始与结束 Git HEAD、改动文件清单、依赖/许可证、真实服务、测试命令与结果、截图/录屏、费用/资源、原始数据变化、PASS/PARTIAL/FAIL/BLOCKED/UNKNOWN、下一阶段接口。

统一证据分级：`USER_OBSERVED` 用户观察；`CODEX_REPORTED` 旧助手自述；`SOURCE_VERIFIED` 文档与源码可定位；`REBUILD_RUNTIME_VERIFIED` Rebuild 隔离环境真实可复现。只有末项满足当前产品验收通过。

## 6. 随包附带的只读仓库守卫

附带 `VERIFY_REBUILD_WORKSPACE.ps1`，是可在 Windows PowerShell 下使用的**只读校验模板**。它先确认固定主项目本身是 Git 顶层，然后判断传入的候选工作目录是否与该主项目拥有相同 `git common-dir`。可识别来自 Rebuild 的 Git worktree，但拒绝错误 Silver-economy 仓库。**本次尚未在你的 H 盘运行，需 Codex 在 P00 实测并视仓库真实结构适配。**
