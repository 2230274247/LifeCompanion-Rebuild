# P05｜不仅会聊天：资料查询、出行协助、语音与主动回访

## 定位

这一步是从“可聊天的日记/提醒器”升级为**真实帮助用户处理生活事务的助手**。重点是**工具真实执行**而不是 LLM 假装查过资料、天气或路程；主动关心必须基于明确授权、真实事件和适度的频率控制。

## 05-01. Tool Registry 与受控工具调用

- 优先调查 Rebuild 的 LibreChat Agent、MCP、Tool Calling、已有插件接口；只补一个统一受控 `Tool Registry` 和 `Tool Execution/Audit` 层，不再造一个独立大语言模型聊天系统。
- 每类工具必须有：名称、功能、作用域/用户权限、参数 Schema、业务前置条件、执行状态、来源和时效、请求超时、配额、错误恢复、敏感数据出网清单。
- 对非变更型工具（公开网页检索、天气、地图路线）可按用户意图执行；对需要替用户向外发送信息、修改/删除数据、预约支付等有外部影响的动作必须显示具体操作和请求确认，形成业务回执。
- 提供“AI不知道/需要实时数据时不凭空编结果”的降级。搜索结果应包含标题、来源 URL、获取时间；地图/天气包含查询时刻、地点、估算范围/不确定性。

## 05-02. 查询资料与日常助手

- 通用资料搜索：自然对话问问题 → 判断是否需实时搜索 → 调用已有可用的网页/搜索 API → 引用可核查来源与时间 → 适度总结；不能从模型训练知识冒充当日实时资讯。
- 个人历史查询：使用 P02 授权记忆检索；区别用户提过的事实与网络公开资料，避免张冠李戴。
- 行程：用户说“明天去某地做客，需要早点出门吗？” → 先识别起点/目的地是否已由本人授权提供；缺关键起点只问一项；调用真实路线 API 得到行程估算；必要时结合真实天气并提供“建议出门时间”和可编辑提醒卡。没有地图 API 的情况下，不能假装知道实时车程。
- 如用户授权，支持待办/提醒状态查询（来自 P03），以及非打扰性的“你之前提到要处理这件事，现在需要帮忙吗？”

## 05-03. 语音和方言（不要把“能录音”当作“识别成功”）

- 先审计已有 Web Speech/音频播放器/云 STT/TTS；综合国内网络、费用、隐私与方言支持情况，从已批准可用 provider 中选择，不强制安装本地语音模型。
- V1 最小闭环：按住/点击输入 → 浏览器授权录音 → 合法语音转文本 → 用户可纠错 → 发聊天 → AI 文字答复 → 可选朗读；错误时可退回文字输入。
- 方言能力（如吴语/地方口音）必须通过真人授权或合成测试集测 WER/CER，**不能声称默认就支持所有方言**；无法识别时提供文字或普通话备选，不强迫上传原始音频。
- 音频保留期限、删除、敏感内容上传与录音指示明确；无用户允许不后台录音。

## 05-04. 主动回访系统

- 回访只来自用户已确认/允许的事实、待办、事件或特殊纪念日；不要靠“AI觉得关系亲密”无限制主动推送。
- 回访策略至少分：时间触发（生日/行程前）、事件触发（用户提过的后续进展）、服务触发（提醒完成后的可选跟进）、用户主动设置。全部可开关、设静默时段和频率上限；提供“这件事不再问”。
- 回访实例：用户昨天提过周五见朋友，周五之后用户重新打开 App 时可在首页看到轻量的“上次你提到要去见朋友，后来怎么样？”；如要主动推送，须单独得到通知授权。
- 已删除事件、授权过期、用户拒绝、低信度、私密内容不触发；避免反复问、问错日期、误把计划当成已发生事实。
- 所有提醒/回访使用现有 scheduler/outbox（P03），以可重试且幂等的 job/status 为准；不创建第二个无监管的 cron 系统。

## 05-05. 有用也要自然

- 聊天语气可适度拟人、礼貌、有上下文，但不能强行装作真人、不能未经用户许可产生亲密/排他关系或推断其感受；允许用户选“简洁/自然/温和”，避开冗长工程口吻。
- 支持“少打扰模式”、自适应信息密度；对无需要任务的普通聊天，不强行弹推荐卡、搜索按钮、创建图片或日程。

## 验收门槛

| ID | 用例 | 验收证据 |
|---|---|---|
| TOOL-01 | 问一条需要实时信息的问题 | 有真实搜索调用、来源链接与时间，失败可解释 |
| TOOL-02 | 问天气与出行时间 | 实际天气/路线来源、地点正确、查询时效、可转为提醒草稿 |
| TOOL-03 | 无搜索/天气 API 时查询 | 说明不可用/不确定，不编造实时结果 |
| TOOL-04 | 工具超时、限流、费用超限 | 不丢聊天，错误可恢复，日志脱敏 |
| VOICE-01 | 浏览器语音→转写→聊天 | 全流程实际运行；音频权限与数据删除明确 |
| VOICE-02 | 地方方言不支持 | 显示备选输入，不假称已理解 |
| FOLLOW-01 | 行程后非侵入式回访 | 基于真实存储事件、正确时区、频率限制 |
| FOLLOW-02 | 关闭回访/静默时段 | 不再触发，重启后设置仍生效 |
| FOLLOW-03 | 未授权的私密事件 | 不主动发消息或推送 |
| UX-02 | 语气和建议卡 | 自然、不喧宾夺主，无内部技术状态泄漏 |

- 开始前真实执行 P00 的项目身份校验；记录 `canonical_root / git common-dir / branch / HEAD / worktree / active Compose project / test DB`。只有已核实的 Rebuild 隔离开发工作区可写。旧 `Silver-economy`、`Silver-economy-research`、`.work/intelligence-20261103` 全部只读。

- 能复用上游成熟开源组件时优先通过受控版本的 API/适配器集成；不直接改上游镜像源码、不重复创建同功能主系统；clone 只是获得代码，不等于集成完成。第三方必须记录许可证、版本、NOTICE、可能的传染性义务及安全公告。
