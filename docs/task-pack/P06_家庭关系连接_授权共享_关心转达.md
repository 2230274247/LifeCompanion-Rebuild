# P06｜家人、亲友及未来关系网络：以双方授权为中心的连接能力

## 为什么是独立阶段

用户的未来设想不只是 AI 和个人聊天，而是**让人和人之间通过自己的 AI 产生温暖连接**。但如果允许某个家人“问 AI 我今天在哪”，产品很容易从关怀工具滑向未经许可的监控工具。因此必须坚持“明确邀请、双向同意、逐项授权、默认不共享、即时撤销”，确保 AI 不会因为它知道某件事就自动转述。

## 06-01. 建立账号与真实身份关系

- 开发 `ConnectionInvitation`、`RelationshipEdge`、`SharingGrant`、`SharedDigest`、`CareRequest`、`ConsentAudit` 等逻辑对象；表结构按 Rebuild 已有身份库设计，不假定另建 MySQL。
- 用户 A 发出邀请，B 使用自己的身份登录接受；支持 family/partner/friend/other 标签，但标签本身**不自动授予任何访问权限**；未接受/拒绝/屏蔽/解除关系后不得请求私有数据。
- 考虑一个用户多人关联、亲属称谓不对等、昵称和实体图谱的对应关系；**不能把 LangMem 中提到的“妈妈”自动当作注册账号并开放记忆**。
- AI 只能将验证通过且当前有效的关系信息用于响应；不得根据自然语言“我是他妈妈”突破认证。

## 06-02. 细粒度共享与最小披露

授权类别推荐：

1. `CARE_STATUS`：本人主动定义的简短近况/平安状态，不涉及真实定位。
2. `SHARED_EVENT_SUMMARY`：本人选择的已发布日常摘要（可设置仅某天、某段、有效期限）。
3. `SELECTED_RECOLLECTION`：本人勾选的图片/回忆；不能默认分享全部 AI 生图。
4. `AVAILABILITY_TO_CONTACT`：本人选择的“方便联系/稍后回复”等状态；不代表实际地理位置。
5. `CARE_REQUEST_MESSAGE`：允许接收对方“想聊聊/给他带句话”等请求。

**默认不共享**：全部原始聊天、未发布私人记忆、实时/历史位置、精确行程、医疗、财务、亲密关系、联系人名单、其他家庭成员隐私。即使 B 有查看权限，也不能通过组合多条摘要推断超出授权的隐私；对于未成年人需更保守默认设置和适用的监护/安全规则。

Grant 结构至少含 `owner_user_id / grantee_user_id / scope / entity_ids_or_filter / start_at / end_at / revoked_at / version / audit_reason`。所有摘要服务端二次强制鉴权，LLM 不直接决定授权。

## 06-03. 双向家庭关怀交互

### 家人询问示例

用户 B：“今天 A 过得怎样？”

- 若 A 没给任何共享权限 → 温暖但明确：“我没有得到分享当天情况的许可。你可以给 TA 留个问候。”
- 若 A 开启“当天精选近况”且有经过许可的摘要 → 仅在允许范围内答：“TA 今天分享了一件让自己开心的事。”不泄漏原消息或精确行程。
- 若当天没有分享任何东西 → 不编造“应该在上班/应该回家了/大概睡觉”。

### 用户收到关心示例

A 登录后可以看到：“你的家人发来一条关心请求，想和你联系。要不要回个消息？”由**真实留存的请求事件**触发，而不是 AI 在后台统计另一个人私密聊天并自动转述。可以忽略、回复、限制频率或屏蔽。

### 异步转达与关系网络

- 每个“转达”事件有发起人授权、接收人许可、正文/权限、送达状态、撤回限制和来源审计；需要修改或向外发送私有信息时先确认。
- 不把“对方今天查过我几次”作为默认可见情报；披露次数和细节同样涉及对方隐私，须单独、明确授权。推荐用“TA 发来了关心请求”替代监控式提问次数。
- 可以设置“只允许家人看到我主动挑选的当日回忆”，不自动向好友共享完整记忆图谱。

## 06-04. 技术架构与安全

- 身份、授权和审核必须独立于生成式模型； `Policy Enforcement Point` 对每次 API、图查询、相册文件 URL、通知内容进行服务端鉴权。
- 禁止用 Neo4j 关联图谱中已知关系直接解锁用户数据；授权范围只从权威 Grant 库读取。
- 对第三方分享、邀请、对话转达记录审计但日志最小化；邀请链接须防猜测、时效限制、可撤销；禁止直接通过 URL 替换他人 ID 查看信息。
- 邀请防骚扰：黑名单、频控、举报/屏蔽、陌生人默认拒绝，陌生人扩展暂不默认启用。
- 当关系解除、grant 失效/撤回、用户删除素材后，缓存/搜索索引/共享链接/回访任务需尽快失效；撤权后不再生成新的共享摘要。
- 面向家庭使用应保持明确、可读的授权界面，不使用诱导性勾选。

## 06-05. 真实验收用例

| ID | 真实场景 | PASS |
|---|---|---|
| FAMILY-01 | A邀请B/B接受 | 真实双账号关联，拒绝时不建立关系 |
| FAMILY-02 | 无授权直接问A今日行程 | 不透露地点/日程/私人聊天 |
| FAMILY-03 | A只共享某张回忆给B | B只看得到该资产，不能推导/遍历其他资产 |
| FAMILY-04 | A撤回授权 | 立刻失效，缓存、附件、深链不再访问 |
| FAMILY-05 | B发来一条关心请求 | A能选择接收/忽略/回复，AI不编造成员行为 |
| FAMILY-06 | B多次请求/被拉黑 | 限频生效，不骚扰A |
| FAMILY-07 | 非关系账号换 ID 猜测 | API、图、相册、通知均拒绝越权 |
| FAMILY-08 | 删除账户/回忆 | 共享授权和派生资料正确失效 |
| FAMILY-09 | 只有“妈妈”文本但未绑定真实账号 | 不被误当已认证关系或分享对象 |
| FAMILY-10 | 多人家庭与时区 | 各自授权、语言、时区隔离，消息不会送错用户 |

## 给 Codex 的任务提示词

> 执行 P06：在 Rebuild 已验证多用户身份基础上构建双方明确同意的关系连接，先做“家人邀请、可选择的当日摘要/回忆共享、关心请求、撤销权限”闭环。**任何已知记忆不等于可共享**。所有跨用户访问必须以服务端 Grant 鉴权与真实账号绑定为准，不将家人对 AI 的原始提问次数或用户实时行踪默认向另一人透露。首先通过双账号与恶意越权测试，再扩展其他关系；为未成年人使用设置更保守默认。
