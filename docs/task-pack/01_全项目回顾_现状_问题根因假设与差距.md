## B. 最终产品的一句话定义

用户用普通语言说生活，AI **真实帮其完成任务**、**依据可追溯且可纠正的记忆持续理解其生活**，在合适时间**安静地产生个人回忆**，并在**双方明确同意且最小披露**前提下帮助家庭互相关心的生活陪伴型 AI 产品。

它不是：聊天模型加一堆开源后台、自动监控用户、把虚构图片当照片、替家庭成员相互汇报未经授权的行程。

## C. 理想用户旅程（验收必须从这里倒推）

### 旅程 1：日常聊天与真实长时记忆

- 上午聊天 A：“我打算明天带绿色 U 盘，不是银色的。”
- 中午聊天 B：“还有雨伞，天气可能有变化。”
- 晚上另开聊天 C：“我明天带什么？”
- 合格回答：明确**绿色 U 盘（不是银色）和雨伞**，可追溯两处原始来源；没有自动声称任务已经创建。若用户更正颜色，旧事实变为历史而不是两个冲突的当前事实。

### 旅程 2：无负担提醒

- “明天早上提醒我带绿色 U 盘，不是银色的。”→只问“几点？”→显示 2～4 个快捷时间（含其他）→用户点选→真实任务创建→聊天显回执→到时按实际渠道通知。
- “明天下午我要去医院”→AI可以温和建议，但**无明确同意不得创建**；如果约诊时间和出门时间不明确，不能擅自填 9:00。
- “取消刚才那个提醒”→取消真实任务与调度；另开对话仍查得已取消。

### 旅程 3：自然发现回忆

- 用户早上说跑步、吃早餐、开始新计划。系统在经过授权、固定早段结算后，从真实消息衍生的**有效事件记忆**中筛选一个最合适的画面；无需每次询问是否要生图。
- 生成过程在后台静默进行，不发“生图完成”的打扰通知；下次打开“我的回忆”可见最多该窗口一张带“AI 创作”标记的插画/画面，可查看来源、更正和删除。
- 没有足够可靠内容可生成 0 张，不能为了“三段”凑图。

### 旅程 4：真正帮到人

- “明天 15:00 去朋友家，帮我算下多久出门。”→检索经授权的地点、路线和实时天气，给出明确**查询时间、来源、有效期**；路线或天气接口不可用时解释不确定性，不凭语言模型造实时车程。
- 之后可以按已确认的日程提供克制、可关闭的回访或提醒。

### 旅程 5：未来家庭连接

- 家庭成员完成邀请、双方身份确认，用户明确选择仅共享“今天是否平安/是否方便联系”等范围，可按期限授权。
- 家人问“今天过得怎样？”→只能在允许的领域给出温暖、非推测的概述；**不能默认报告实时位置、具体行程、健康细节、私人聊天**。
- 用户打开 AI：“妈妈发来了关心请求，想和你联系；要不要回个消息？”→只有本人许可的请求元数据可转达；拒绝、撤权后立刻停止。

## E. 困扰最久的问题与可检验的根因假设

1. **AI说了不等于业务做了**：模型自由文本输出没有经过实际工具调用/权限确认/持久化回执。根因需追 `LLM → tool → adapter → DB/provider → status`。
2. **上下文记忆被误认为长期记忆**：只传最近 N 条 / 仅按 conversation_id 检索；新会话失忆。需独立用户域长记忆和结构化多条检索。
3. **提醒状态双轨分裂**：建议卡、草稿、任务平台、调度和通知的 ID/status 不统一，取消后语言模型仍引用旧草稿。需单权威任务状态与同步审计。
4. **日期/时间误解析**：时区常量曾显示 `Asia/Hong_Kong`；相对时间用 LLM 自行猜日、带“到杭州后”被错误解读。需 UTC 存储 + IANA 时区 + 显式事件语义与测试时钟。
5. **切页面需重载、链接点击只滚到消息**：来源锚点≠任务详情；可能为路由/稳定 ID/鉴权/前后端代理问题。需从点击到真实后端 ID 的 E2E 追踪。
6. **UI只有“通过测试”却难用**：技术状态泄漏、Markdown `**` 原样显示、输入框 Enter 后残留、模型思考内容默认展示、无效按钮、页面卡顿。需真实用户场景和可访问性测试。
7. **“回忆”与“图片”含义混乱**：Memos 记录、长期事实、当天事件、回忆候选、图片资产被混为一体；需分层、来源与异步任务。
8. **小修小补会破坏别处**：多个框架+旧手搓模块并存；复用同一个 Docker、数据库、身份映射或修改上游源码，造成接口与状态不一致。需契约测试、适配器、独立环境与全量回归。
9. **旧任务改错仓库**：旧记录显示 `Silver-economy/.work/intelligence-20261103` 和 119 变更文件，但不证明这些在 Rebuild。需 Git common-dir、进程/数据库归属、SHA 清单和每条命令写入门禁。
10. **Graphiti 强制却无向量能力**：Graphiti 标准工作流需要真实 Embedding；不可伪造向量。以 Neo4j 结构化关系索引先保业务，Graphiti 实装适配层并诚实报告受阻原生能力。

**上面是“假设与待复核事项”而非已由本次源码验证的根因。**

## G. 架构原则：一次只设一个事实来源

```text
用户浏览器（Rebuild 统一 Shell / 现有 UI）
  │
  ├─ LibreChat：会话、聊天存储、云端模型入口（按实际仓库验收）
  │      │ 保存后可靠事件/outbox + user_id/message_id
  │      ▼
  ├─ Life Core：身份映射、授权、业务编排、证据与状态接口
  │   ├─ LangMem → 权威记忆/事件/证据记录 → Neo4j 查询投影（Graphiti适配另验）
  │   ├─ 意图识别 → LangGraph 交互 → Vikunja/现有任务 API → APScheduler → ntfy/站内
  │   ├─ 事件窗口 → 评分/质量门 → 生图Provider → 私有素材存储 → 回忆详情/Memos
  │   └─ 工具代理 → 搜索/天气/交通/资料（有权限、来源、时效与成本控制）
  │
  └─ Family Permission Gateway：邀请、双向授权、能力级共享、审计、撤销
```

这是**建议逻辑边界，不代表当前项目已有全部模块**。最终以 Rebuild 审计后实际语言、数据库、框架、现有 ORM 与 API 为准。

## H. 阶段执行优先级

- **P00**：冻结唯一项目身份和历史现场，建立所有阶段共同使用的安全门禁。
- **P01**：实际登录、聊天、统一页面、业务卡片跳转、真实身份与基础模型回执。
- **P02**：长期记忆、人物/事件图谱、纠错、跨会话检索和来源。
- **P03**：聊天自然语义到正式提醒和真实通知。
- **P04**：三段自动回忆+静默真实生图。
- **P05**：查询/天气/出行、语音、事件回访。
- **P06**：家庭与其他关系场景，严守双向授权。
- **P07**：后台、可观测性、安全、性能、Ubuntu 和发布门禁。

核心闭环可以依序建立；不是等到所有远期业务都实现才允许得到有价值的阶段成果。

## I. 外部技术依据（2026-11-03 查询；实施时复核）

- LibreChat 提供自托管聊天、多供应商端点、Agent/MCP 机制：<https://www.librechat.ai/docs>。
- Memos 官方提供自托管私有笔记和 REST/gRPC API：<https://usememos.com/docs>。
- Vikunja API v2 从 2.4.0 起可用；新集成应优先对照当前 v2 OpenAPI：<https://vikunja.io/docs/api-v2/>。
- LangMem 具有 `create_memory_manager`/`create_memory_store_manager`，负责根据已知记忆提取和合并，不是现成“全部用户授权”解决方案：<https://langchain-ai.github.io/langmem/reference/memory/>。
- Graphiti 标准架构需图数据库、LLM、Embedder；默认 provider 行为需要显式配置避免意外出网：<https://help.getzep.com/graphiti/getting-started/quick-start>。
- APScheduler 不同主版本持久化及 API 变化明显，实际锁定版本再编写调度代码：<https://apscheduler.readthedocs.io/en/master/migration.html>。
