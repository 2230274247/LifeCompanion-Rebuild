# P02｜跨会话长时记忆、人物与事件时序关系、可纠错知识图谱

## 核心问题

用户最常困扰的是：**AI在当前聊天似乎记得，换个聊天窗口只记住一半；重复对话会变出很多记忆；人物/公司/事件关系混淆；以后追问不能提供原始证据。** 本阶段必须真正解决，而不是修改提示词声称“会记住”。

## 强制架构职责（以 Rebuild 实际主数据为准）

- **聊天原件**：保留现有 LibreChat 的权威会话/消息存储；不让摘要覆盖或偷偷重写原话。
- **业务事实和证据主记录**：保留 Rebuild 现有权威数据库及 ORM/迁移机制；memory/event/evidence/version/consent 为可查询业务记录。
- **LangMem**：真正参与已授权消息的提取、归一化、合并、更新、纠错；使用已有记忆作为上下文，不是每次从零造一堆记忆。
- **Neo4j**：人物、组织、共同概念、地点、事件和随时间变化的关系投影；有 user namespace、有效期、原始来源、删除失效。
- **Graphiti**：锁定可用版本、实现正式 `GraphitiProvider`、检查公开 API/Embedding 需求/LLM provider；若没有真实 Embedding，**不能**声称其原生 episode 全流程或混合检索通过。Neo4j 结构化查询照常真实运行。
- **非向量召回**：事件时间查询、关键词/全文/别名、结构化关系、适当重排；中文召回准确率须测评，不能只测目标姓名完全一致。
- **模型**：调用 Rebuild 当前真实有效云端聊天模型，严格 JSON/Pydantic 验证；Embedding 默认为 `DISABLED_NOT_CONFIGURED`，不伪造数值向量、不擅自新付费服务。

## 02-01. 统一数据语义和关联

至少明确区分 `ChatMessage`、`MemoryItem`、`MemoryEvent`、`MemoryEvidence`、`Entity/Relation`、`Recollection`、`Reminder`；映射 `user_id → conversation_id → message_id → memory/event_id → graph_projection_id`。时间包括事件发生时间与系统获知时间；事实包括肯定、否定、引用第三人、疑问和不确定性。

按 Rebuild 原生 Schema 扩充，不造第二份相同主库。每条事实有 `source_message_ids`、生效期、可信度、用户纠错版本。用户删除原消息或撤授权后派生图和回忆必须失效/重建。

## 02-02. 提取、去重、纠错、历史

`聊天已提交 → 授权检查 → 可靠 outbox → LangMem 提取 → Pydantic schema → 用户域旧事实召回 → 实体消歧 → create/merge/update/mark_historical/needs_confirmation → 权威库保存 evidence → Neo4j 增量投影/重试 → 索引对账`。

- 只在有来源的情况下持久化；“朋友邀请加入公司”不等于用户已加入。
- `memory_strength`（长效重要度）和 `recollection_score`（该时段值得留念）严格独立，出现次数仅弱特征。同会话机械重复不能无限加分。
- 好友甲和好友乙分别属于不同公司，共享“初创公司”概念**不代表同一个公司/人**。
- 小王从甲公司换到乙公司：旧事实保留历史，当前查询返回乙公司；日期不明不编造。
- Neo4j/LLM 故障不丢聊天；异步任务幂等重试、死信和人工复查。

## 02-03. 跨会话问答与回溯

- 不只取最近 N 条聊天，而是根据当前 `authenticated user_id` 在所有授权会话与记忆中组合召回；包含结构化筛选 + 中文词组/别名 + 时间条件 + 多候选合并。
- 回答必须先取得来源有效、仍授权的证据；提供“查看原对话/查看记忆详情”，查不到时明确说未找到。
- 记忆查询需支持“最早何时提到”、“谁邀请我”、“目前在哪工作”、“和哪几个人讨论创业”、“明天带哪些东西”。
- 用户可手动纠错/隐藏/删除、指定重要记忆；纠错与删除后缓存、图谱、旧事件引用不能复活。
- 引入独立记忆诊断面板供开发测试，普通聊天只看可理解的回答，不泄漏内部工程日志。

## 02-04. 测评体系（严禁只用100/100简单词匹配作弊）

- 至少 100 组事实合并/冲突/否定/实体消歧/时间变化；至少 100 组自然口语跨会话检索，含无需提实体名称、错字、同义短句、两个相关候选/负样本、变化事实。
- 输出准确率、错误合并/漏合并、Precision@k/Recall@k/MRR、延迟 P50/P95、人工复核样本、真实云端调用费用。
- 结构化输出有效率、写入重试、图投影一致性、跨用户隔离、撤回/删除传播单独统计。
- 旧工作树曾报告 571 项、100/100、F1 等，仅可迁移**测试样例**并在 Rebuild 重跑，不可继承通过结论。

## 必做用户场景

1. `MEM-01` 会话 A 提“绿色 U 盘，不是银色”；B 提“雨伞”；C 问明天带什么：两条同时召回，否定限定条件不丢。
2. `MEM-02` C 继续问“我何时提过 U 盘？”：可打开 A 的来源。
3. `MEM-03` 用户说“改成蓝色 U 盘”，当前结果只输出新颜色，旧记忆可追踪但不误当当前。
4. `MEM-04` 三个朋友、两家不同公司、邀请与就职的 12 天事件顺序；历史与当前关系正确。
5. `MEM-05` 新设备/新会话/服务重启仍检索；同一消息重放不生成重复记忆。
6. `MEM-06` 删除消息/关闭授权/跨账号替换 ID 不泄漏，不召回已删除数据。
7. `MEM-07` Graphiti 无向量门禁独立报告，不假装完成原生检索。

## 完成定义与交付

跨会话召回、权威证据、更新与删除、权限、Neo4j 真实结构化问答、LangMem 真实调用均在 Rebuild 隔离环境通过；Graphiti 原生仅在确有可用 Provider 时验收，否则 `BLOCKED_EMBEDDING`。输出 `MEMORY_SCHEMA.md`、`GRAPH_SYNC_RECONCILIATION.md`、`GRAPHITI_NATIVE_STATUS.md`、`RETRIEVAL_EVAL.md`、`MEMORY_E2E.md`、`P02_STAGE_LOG.md`。
