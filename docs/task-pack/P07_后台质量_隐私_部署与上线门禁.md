# P07｜后台管理、可靠性、UI质量、依赖安全、部署与最终回归

## 阶段定位

当 P01～P06 的功能已能使用后，要成为**长期稳定运行、可扩展、可维护、成本可控**的产品。本阶段并非最后才开始安全检查：所有前期阶段也必须有权限、迁移和回归门禁；这里只做跨模块总集成和运营级加强。

## 07-01. 后台管理

在 Rebuild 原生管理框架或成熟开源管理 UI 中增加可授权的管理员界面，最小功能：

- 总览：真实用户数、活跃用户、时段使用量、完成聊天数、记忆处理队列、回忆候选/发布、提醒创建/到期/失败。
- 用户：启用/禁用、角色、绑定的第三方服务账号、账号异常、授权版本。**管理员不默认浏览用户私聊内容**；调试应只看匿名统计和经授权的单次排障证据。
- AI：按任务类型（聊天/记忆抽取/评分/生图/工具/语音）展示 model/provider、Token、成本估计、失败、延迟、预算上限与配额。
- 记忆：失败待处理数、来源断链、图投影/主库差异、重复事实和歧义率、删除传播结果。
- 回忆：时窗执行结果、筛选跳过原因、成功文件存在性、失败重试、用户纠错/下架。
- 提醒：草稿、正式任务、待到期、投递尝试、设备端送达未知、过期任务、重复/失败计数。
- 关系：邀请滥用与高风险访问拦截的**非内容化统计**；Grant 撤回生效记录。
- 运营：服务健康、依赖许可证和 CVE、备份、日志和可选告警；所有操作需 RBAC 和审计。

## 07-02. 安全与数据治理

- 建立数据分类与保留期：原始会话、长期记忆、事件、图片、音频、任务、通知、授权审计、调用日志。加密传输，受控文件存储和私有文件 URL。
- 用户可以导出、纠正、删除、撤回长期记忆/自动生图/关系共享授权；删除向派生图谱、向量索引（如有）、Memos、图片缓存、任务和通知传播，记录完成/待重试状态。
- 云端模型调用对敏感内容最小化出网，确保开源库不绕过受控模型路由调用未授权默认云服务；Key 不进入前端/日志/Git。
- 管理员权限、跨用户 IDOR、邀请滥用、供应商 Webhook 真实性、SSRF（网络工具）、回忆文件签名 URL、通知内容泄漏须有专项安全测试。
- 接入中国大陆用户前，明确个人信息处理、隐私告知、第三方云服务数据处理/跨境等适用法律与平台政策；无法核实的合规要求列为上线前独立人工审查门槛，不假称已经合规。

## 07-03. UI/UX 最终验收

保留 Rebuild 实际已冻结的主题 Token，不以旧 Vue 文档全量替代。全部主视口 `390/430/768/1440/1920` 检查：

- 内容对比度、字号与适老化辅助选项、滚动、状态反馈、触控可点、菜单与弹窗、软键盘遮挡、焦点恢复、屏幕阅读器。
- 聊天、记忆、回忆、提醒、设置与关系邀请跨页的共享感，不能切换后强制整页白屏/重新登录。
- 动画应服从现有 Motion Token，`prefers-reduced-motion` 生效，图片过渡稳定；不要因为华丽动画影响功能。
- 内部日志/Provider 名称/模型思考不暴露在普通用户主界面；需要调试时仅在受控开发工具展现。
- 每条按钮都必须有真实效果，正确 loading/success/error，避免“看起来能点其实没做事”。

## 07-04. 工程架构与可维护性

- 锁定 LibreChat/Memos/Vikunja/ntfy/Neo4j/LangMem/LangGraph/APScheduler/Graphiti 等版本、镜像 digest（可行时）、许可证/NOTICE、更新和安全公告；现有上游补丁清单独立保存，避免下一次升级丢失。
- 统一跨服务 Schema 与 API 契约、错误码、用户授权、来源 ID、时间字段、事件 outbox、idempotency_key；OpenAPI/类型生成按仓库现有做法，避免多 Agent 写出不兼容代码。
- 数据库迁移必须增量、可回滚且先在克隆 DB 试运行；保留原生产数据及素材，不强制覆盖。
- 分层服务/模块保持“单一权威事实来源”，不因多个开源服务引入多个互相打架的业务真相。
- 提供成本预算和可靠性面板；限制无限 AI 重试和自动生图费用。

## 07-05. Windows → Ubuntu 部署

- 必须使用独立 Docker Compose project 名称、持久卷、网络、健康检查和秘密注入方式；不使用本机绝对 H 盘路径作为服务器运行依赖。
- 优先复用已有云端模型 API；不部署本地大模型、Embedding、Laya、Ollama/vLLM。
- 提供可测试的一键启动/停止、数据备份/恢复、数据库迁移、日志定位、告警、访问控制与 TLS 接入说明。
- 如开发机内存有限，不为启动 Rebuild 无故关闭其他服务，不跨项目复用数据卷；可以针对独立测试环境限流、分批测试。
- 公网发布**必须有明确授权与安全复核后才执行**；Windows 本机 Compose 成功不等于 Ubuntu/公网验证通过，更不等于 Android 原生通知/APP 已交付。

## 07-06. 全链路故障演练

1. 用户聊天成功但 Neo4j 断开：消息保留、图投影待补，不假报记忆完成。
2. 任务已创建后 scheduler 重启：不会丢提醒、重复触发。
3. ntfy 接受后终端离线：显示“通道已接受/送达未知”，不可假报设备收到。
4. 图像 API 失败：不会有虚构图片链接，相册可呈现文字候选/失败状态。
5. 数据库迁移失败：测试备份恢复成功，旧数据核对无误。
6. 用户撤回许可：关闭新的模型出网、提醒/生图/分享任务并清理派生，按产品策略处理已有记录。
7. 模型调用 429/超时/预算不足：重试边界受控、可恢复且有成本记录。
8. 关系连接用户越权：API/相册/图谱/任务/通知都不能读私密内容。
9. 设备宽度变更、浏览器刷新、跨会话、多账号并发：状态无错乱。

## 全阶段共同执行规则（本阶段必须实际遵守）

- 开始前真实执行 P00 的项目身份校验；记录 `canonical_root / git common-dir / branch / HEAD / worktree / active Compose project / test DB`。只有已核实的 Rebuild 隔离开发工作区可写。旧 `Silver-economy`、`Silver-economy-research`、`.work/intelligence-20261103` 全部只读。
- 先读 Rebuild 现有 README、AGENTS.md、设计规范、测试、迁移和用户授权；未知路径不可凭旧方案猜测；以 Rebuild 实际代码做增量变更。
- 能复用上游成熟开源组件时优先通过受控版本的 API/适配器集成；不直接改上游镜像源码、不重复创建同功能主系统；clone 只是获得代码，不等于集成完成。第三方必须记录许可证、版本、NOTICE、可能的传染性义务及安全公告。
- 禁止擅自使用生产用户数据做测试、批量重写数据库、覆盖原素材、泄露密钥、修改授权、未授权付费、打开公网、推送 Git、合并主分支。测试采用独立环境、合成用户、经过校验的备份和可回滚迁移。
- 真实云端模型只用 Rebuild 已验证可用的供应商和后端 Key；不下载 Qwen/Laya/Embedding 本地权重，不默认新增百炼 Key。明确预算与调用限额；API 未配置或余额不足时用 `BLOCKED_API_CONFIG` 报告真实云调用未验收。
- 每个任务保持 `证据→假设→修复→单测→真实集成→Playwright/浏览器→回归→记录`。不得仅依据页面文案、Mock、内存变量、接口 200、旧项目测试数字写 PASS。
- 每阶段**新增独立 Markdown 开发日志**，提供命令、退出码、前后 Git Diff、真实请求/响应（脱敏）、DB 验证查询、截图/录屏、成本和依赖版本。只用 `PASS/PARTIAL/FAIL/BLOCKED/UNKNOWN/UNVERIFIED`。
