# P01｜聊天真实闭环、统一入口、跨页导航、账号与 UI 基础体验

## 核心目标

把 Rebuild 从“多个开源系统拼起来能看到页面”变成**一个可以连续使用的产品**：用户登录后能聊天、切页不掉状态、可查看真实业务详情、刷新可恢复；业务事件都关联同一个可靠的用户身份和消息来源。**不重新手搓 LibreChat 聊天内核。**

## 实施内容

### 01-01. 现有开源能力实测与最小修改

- 优先审查 Rebuild 的 LibreChat 版本、云端模型 provider（可能是 DeepSeek/GLM 或其他实际可用配置）、消息真实入库路径、接收/输出 SSE、历史会话、流式中断、重试与消息幂等。按仓库真实代码做适配，不能假定 Vue3。
- 审核 Memos 的写入链路：聊天事件是否通过 life-core 稳定关联 `user_id / conversation_id / message_id / memo_id`；别把 Memos 笔记当成长时记忆全部实现。
- 模型路由统一后端访问，不暴露 Key；模型请求/响应的合法工具调用和实际业务保存分开记录。出现模型空回应、429、余额不足、过滤或格式不符时，保留用户输入并显示准确失败状态。
- 对“已保存消息但无 AI 回复”“Mock 看似真实回复”“保存后渐进显示伪装上游 token 流”等加回归测试。

### 01-02. 单页壳和跨业务稳定路由

- 统一首页、聊天、记忆、回忆、提醒、个人设置；评估现有 React Shell/路由，不新建平行 UI。保持 Ember（若真实存在）的设计 Token、React 或其他 Rebuild 现有生态。
- 真正连接 `聊天中的业务卡片 → (reminder_id / memory_id / recollection_id) → 后端鉴权查询 → 详情页`；“查看原对话”单独定位 message_id，不能混用“去详情”。
- 点击、键盘、浏览器刷新/前进/后退/深链接/手机底栏均可达；未创建时不生成假链接；用户取消/删除后有明确历史状态而不是死链。
- 修复路由因前端代理、跨域、接口 401/403/404、业务 ID 不一致导致的页面重载或白屏；逐条贴出真实根因代码。

### 01-03. 统一身份和权限

- 编制 LibreChat → life-core → Memos → Vikunja/ntfy 的**跨服务身份映射图**，不能用所有用户共用一个服务账号的身份来替代访问控制。若仍单用户映射，明确标 `PARTIAL`，在 P01 完成可安全扩展的身份映射与服务端授权。
- 业务服务不能信任前端传入的任意 `user_id`；所有查询/写入必须根据认证主体校验。真实 2～8 个隔离账号交错验证。
- 对登录、退出、刷新 token、过期会话、修改账号/密码、未授权详情链接、多人并发操作进行测试。允许保留现有 SSO 方案但不得伪造已经完成。

### 01-04. 用户痛点专项

- Enter 发送后输入框是否清空：仅真实提交后清空；输入法组合输入不误发；失败可恢复。
- 正确渲染 Markdown，避免 `**` 原样泄漏；思考/工具日志默认折叠或只在调试模式展示；不显示“记忆提取未完成”“transport=”“provider=”“后台已入队”等普通用户不需的内部诊断。
- 无意义按钮（点击无动作/只有一个备选项）移除；发送、加载、成功、失败、重试、空列表都有即时反馈。
- PC/移动端（390、430、768、1440、1920）检查弹窗触控、导航、字重、文字对比、Focus、减少动态效果；动效不能掩盖真实状态或导致滚动卡顿。

## 必做测试用例

1. `CHAT-01` 真云端聊天、历史刷新、重启后消息恢复，真实 token/请求状态有证据。
2. `CHAT-02` 模型故障时消息安全且失败可重试，无假“已经保存提醒”。
3. `NAV-01~04` 聊天中正确打开提醒、记忆、回忆详情，浏览器返回、深链接、手机底栏无整页重载。
4. `AUTH-01` 同一身份跨框架映射稳定、删除/退出/重登正确，不能越权读别人。
5. `UX-01` 中文输入法、Enter、Markdown、思考隐藏、无效按钮与异常状态有真实浏览器证据。
6. `REG-01` Rebuild 原有的 LibreChat、Memos、UI 测试无阻断回归。

- 开始前真实执行 P00 的项目身份校验；记录 `canonical_root / git common-dir / branch / HEAD / worktree / active Compose project / test DB`。只有已核实的 Rebuild 隔离开发工作区可写。旧 `Silver-economy`、`Silver-economy-research`、`.work/intelligence-20261103` 全部只读。
- 先读 Rebuild 现有 README、AGENTS.md、设计规范、测试、迁移和用户授权；未知路径不可凭旧方案猜测；以 Rebuild 实际代码做增量变更。
- 能复用上游成熟开源组件时优先通过受控版本的 API/适配器集成；不直接改上游镜像源码、不重复创建同功能主系统；clone 只是获得代码，不等于集成完成。第三方必须记录许可证、版本、NOTICE、可能的传染性义务及安全公告。
- 禁止擅自使用生产用户数据做测试、批量重写数据库、覆盖原素材、泄露密钥、修改授权、未授权付费、打开公网、推送 Git、合并主分支。测试采用独立环境、合成用户、经过校验的备份和可回滚迁移。

- 每个任务保持 `证据→假设→修复→单测→真实集成→Playwright/浏览器→回归→记录`。不得仅依据页面文案、Mock、内存变量、接口 200、旧项目测试数字写 PASS。
- 每阶段**新增独立 Markdown 开发日志**，提供命令、退出码、前后 Git Diff、真实请求/响应（脱敏）、DB 验证查询、截图/录屏、成本和依赖版本。只用 `PASS/PARTIAL/FAIL/BLOCKED/UNKNOWN/UNVERIFIED`。
