# P04｜从真实生活事件到早/中/晚静默生成图片回忆

## 核心产品体验

让用户不必每天写日记、选照片、点生成按钮。只要在某时段有普通聊天，系统经过用户的**事先明确选择**就能在固定时刻挑选这个时段**有证据、值得保存的事件**，必要时使用真实云端图像 API 创作一张画面，静默进入“我的回忆”。当用户自然打开 App 时才发现，而不是打扰式推送。

## 04-01. 严格区分五种对象

- **聊天原文**（不可被图像文本覆盖）。
- **事件记忆**（某天、某时、谁、做了什么、情绪线索，能追溯消息）。
- **回忆候选**（某个时间窗有多少件真实事件、评分和不发布理由）。
- **生成任务**（待执行、调用 provider、异步轮询、重试、失败、成本、去重）。
- **回忆资产**（真正图片文件、存储地址/哈希、AI 标识、关联事件/来源、删除权限）。

Memos 已有的文字 Memo 不等于回忆生图；给前端假图片地址、返回 base64 模板或空文件均不能算成功。

## 04-02. 产品时间窗：用户设置可调整

- 初版默认候选（须以产品配置持久化而非硬编码）：**早 05:00–11:00、午 11:00–17:00、晚 17:00–23:00**，参考出图结算 11:00、17:00、23:00；**用户明确确定的只有“早 11:00 示范”**，午晚可在默认配置里设置且明确可更改。
- 23:00～05:00 不丢失：可归入下一早段并在配置文档中公示（其他合理规则可选，但须固定且测试跨日），时间窗为半开区间、同一条消息只属于一个窗。
- 按用户 IANA 时区计算；记录“消息写入时间、事件发生时间、窗口结束、任务开始、发布完成”不同时间。
- 用户未聊天/未授权/无足够真实事件/敏感事件需排除 → `SKIPPED`，当天可以 0、1、2、3 张。

## 04-03. 智能筛选（最重要，不能关键词硬凑）

`已授权窗口内的真实消息 → P02事件记忆与来源 → 时间与身份核查 → 候选聚合与去重 → 结构化模型多维评分 → 来源/隐私/重复/完整度质量门 → 最多1件 → 创作提示词/文字回忆 → 出图作业`。

评分至少：个人意义、首次/独特度、用户表达的感受、事件清晰度、来源充分性、与时段相关度、私密性适宜度、重复/发展性。长期记忆重要性 `memory_strength` 不能直接代替 `recollection_score`；高情绪不必然应生成图。

不要求用户确认每次生成，但**第一次必须明确授权**，并能在设置关闭、更换时段、纠正“不值得保存”、删除衍生素材。对敏感内容和他人私人信息需更严格默认排除；首次生成或管理员/测试用户使用沙盒素材。

## 04-04. 真实图像 Provider 集成

- 必须先盘点 Rebuild 当前已可用云端图像接口、网络、余额、版权/隐私/区域、实际响应格式，不能把历史未验证的“免费 API”声称有稳定额度或生产可用。
- 定义 `ImageProvider` 适配器：`submit(prompt, config, idempotency_key)` / `poll(job_id)` / `download` / `metadata`；所有密钥服务端管理，有超时、限流、失败回退与成本上限。
- 使用同一事件源文本构造“可视化**创作**提示词”，不能增添没有来源的人名、衣服、具体住址、疾病、天气、肖像照片真实性细节。用户不提供真实照片时，宜做象征性插画/情景画，不假装一比一还原。
- 保存**真正可读取且能通过哈希验证的图片文件**于受控私有资产存储，DB 保存与 source IDs 的引用。默认不额外通知，用户打开相册时按产生时间自然出现。
- 如图像 API 未提供/未经许可或费用阻塞 → 允许完成**文字回忆+真实候选和 job 状态**，单独标记 `BLOCKED_IMAGE_PROVIDER`；不得把 mock 图冒充已生图。需要在下一步继续查找已有可用合法 provider，而不是未经授权开新收费账户。

## 04-05. 相册和来源回查

- 保留 Rebuild 的“我的回忆”列表/相册/时间轴；按日/早午晚展示 0～3 张，支持点击进入详情、查看具体来源消息、回忆事件、AI 创作标识、隐藏/删除/反馈。
- 从聊天或事件也能跳对应回忆；任务未结束时显示真实“待生成/处理中/失败/文字版”而非空图。
- 图像去重与重新生成必须幂等；若消息被删除、授权撤销或事实被纠正，相关资产进入需处理队列，不允许留存失效的个人敏感素材。
- 图像成功但页面不可见、页面显示但文件不存在都视为失败。

## 04-06. 模拟一天的真实回归

- 早：06:30 跑步 3km，早餐补充营养，聊天重复跑步后续进展；筛选一件真实最有意义的事情，不应无缘无故添加第二个人物或天气。
- 午：日常学习和一次特殊探访，两件候选正确排序，有理由码。
- 晚：说“晚安”无其他事件，必须 SKIP。
- 次日用户离开应用后返回，仅相册新增相关图片，**不会收到生图完成推送**。
- 故障：图像 provider 超时、任务重启/重复执行、跨日期/时区、删除源消息、撤授权；不得重复图片，不得失控消费 API。
