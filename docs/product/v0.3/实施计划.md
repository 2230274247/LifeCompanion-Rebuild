# V0.3 A→B→C→D 实施计划

2026-11-04，Asia/Hong_Kong。基于完整附件及本次仓库审计；本文件描述待执行工作，不代表功能已完成。

## 1. 实施假设与边界

1. 代码实施基线是 `.work/p00-p07-20261103` 的既有 P03/P04 成果；
   canonical main 仅作为较早基线。本轮原始规格和审计交付位于 canonical `docs/product/v0.3`。
2. 采用文档推荐时间方案 A，IANA 用户时区、UTC 持久化，静默归档、每天最多三张。
   方案 B 不作为默认；旧用户自定义 ends 不无声重置，迁移时保留原值和策略版本。
3. 沿用 LibreChat React、FastAPI/httpx/SQLite、Memos 官方 API、P04 八维评分和 P03 调度；
   不重写聊天/长期事实/提醒，不新增相册 App，不额外部署调度器或消息队列。
4. 生图必须独立配置 Provider、凭据、用途授权和硬预算，不能把 DeepSeek/智谱聊天授权当成 Kolors 授权。
   当前真实 Provider 条件未满足，阶段 B 真实验收标 BLOCKED；A 不依赖其可用性。
5. 本期仅静态普通卡。rarity/card_effect/effect_version 在 D 以可空兼容字段加入，
   不分配概率、不加微光/镭射动画、不引入 Atropos。
6. 全部写入和迁移验证使用独立 V0.3 合成验收库、私有目录和未占用的回环端口。
   不修改生产/原始用户数据，不恢复旧 P05 请求，不自动部署公网或推送 Git。

完成定义：0/1/2/3 个合格事件都得到准确结果，无聊天/无授权/无合格事件不进入生图；
重启、重复触发、并发、时区切换与 DST 下保持数据库约束及来源可追溯。

| `app/memory.py` | 原则上复用不改；只有来源字段契约确有不足时做最小补充，不重写记忆 key 或回填虚构证据 |

模型映射：

- `moments` 继续作为结算与最终回忆实体，补 `local_date`、窗口 UTC 边界、
  `settle_after_utc`、`policy_version`、稳定状态理由；保留旧 ID/字段兼容。
- 对有 V0.3 业务日期的记录建立 `(user_id, local_date, slot)` 唯一约束；
  **不能把 policy_version 加入唯一键而允许同一天同槽重发**。
- 保留旧窗口/旧数据，不凭结束时间猜测历史业务日后批量改写。
  历史重复先生成冲突报告；未经授权不删记录、不强行建失败的唯一索引。
- `recollection_candidates` 复用为候选/拒绝/聚合来源记录；引用本人原消息及事件 ID。
  同一次事件合并，不把同日两次独立跑步误合并。不足证据保守跳过或仅文字。
- 空窗口/无授权记录审计理由，SKIPPED 不显示为错误，也不调用生图。
- 时区变更采用版本化生效边界，冻结已有结算；未结算时间区间不重叠、不遗漏。
  非整数偏移、DST 缺失/重复当地时间都以 UTC 范围实测。
- 生图授权关闭不应阻断已有文字回忆链路；文字与外发图片权限分目的校验。

调度策略：P03 的 scheduler factory 已存在，先验证该独立进程实际存活、
JobStore 恢复和单实例归属，再开 external 标志。没有存活证明时不关闭既有调度路径。
结算 callback 仅写持久意图，图像/模型耗时不阻塞 scheduler；任务消费沿用现有业务 Worker。
不能仅安装 APScheduler 后再启动一个与 P03 无关的服务。

验收命令/证据：

1. 聚焦 pytest 固定时钟回放 T01～T07、T13～T14、T23；覆盖 00:00/11:00/16:00/24:00 排他边界。
2. 独立 DB 多连接/多进程原子插入、重复 callback、进程重启，检查唯一结算及外发请求计数 0。
3. 合成事件经既有来源 API→候选→受控评分，Mock 与真实评分分别记录；无预算时不云调用。
4. 回归既有聊天入队、权限、Memos、提醒；真实时钟使用测试配置，不改机器时间或原用户数据。
5. 保存 schema 前后、迁移两次运行结果、窗口 UTC 快照、候选理由、测试日志及同尺寸基线截图。

阶段门：A 的业务验收通过后进入 B；A 无需等待 Kolors 密钥。当前状态 PARTIAL（仅审计完成）。

## 3. 阶段 B：真实 Kolors、持久任务、私有媒体

完成定义：虚构事件经真实 Kolors 输出，后端安全获取、完整校验、私有保存，
正确用户授权读取，错误用户拒绝，拥有真实请求标识、SHA-256、尺寸和耗时证据。

| 计划变更 | 新增/复用理由 |
| --- | --- |
| `app/image_provider.py` | 小型统一契约及明确 Mock/Kolors 实现；取代现有业务内硬编码 CogView 调用 |
| `app/image_jobs.py`（确需拆分时） | 利用 SQLite 原子领取和既有 Worker，补幂等、租约、结果核验、分步发布恢复；不新起任务框架 |
| `app/media.py` | 当前缺完整私有媒体能力；负责可信下载、解码、缩略图、文件原子写入及 owner 读取/删除 |
| `app/moments.py`、`store.py`、`main.py` | 保持 moments 与 Memos 文字关联，接入任务/媒体元数据，不另建平行回忆产品 |
| `app/config.py`、`.env.example` | 独立图像凭据引用、可信 host、大小/像素上限、额度/费用上限与超时配置；不提交实际秘密 |
| `requirements*.txt` | 仅为完整解码/缩略图增加必要、已核验许可的图像库；不凭间接依赖认为已安装 |
| 网关 `server.mjs`、data-provider | 精确放行媒体/操作路由；禁止暴露内部任务与服务凭据 |
| Provider/job/media 测试 | HTTP 合同 Mock、真实烟测各自独立，覆盖 T05～T12、T17、T20～T22 |

数据最小扩展：

- 增加 `image_generation_jobs`，关联现有 moments：唯一幂等键、provider/model、
  provider_job_id/request_id、attempts、lease_owner/expiry、next_retry_at、分类错误、
  模板版本和真实/Mock 标识。新增原因是现有 moments 没有供应商请求恢复契约。
- 增加媒体元数据，绑定 owner/moment、随机私有 storage key、MIME、width/height、
  bytes、sha256、thumbnail、审核结果、状态。文件放受忽略的独立私有目录，
  不挂到静态站点，不把可猜 URL 当权限。
- 事件与文字继续走已存在 events/Memos；图像挂载到已有 moment。
  先建立私有待发布资产，再幂等关联/发布；存储或 Memos 写入失败可恢复，不再生成一张。
- 明确 opt-in 的 Provider/隐私用途/consent_version 和撤回时间。
  旧 bool 不自动变成向新供应商外发的授权。入队、调用前、发布前均复核，
  授权撤回与在途取消不发布迟到结果。

安全与错误行为：

- Prompt 从 confirmed_facts/unknown_facts 结构构建；不传整段私聊、姓名、
  手机、精确家庭地址、病历等。未知人物使用非身份化构图。
- 真实 API 的数据留存/地域/商用和输出存储权限需要供应商官方说明及账户实际验证。
  本轮不把“模型开源”或旧文档的假设免费额度当成已获调用权限。
- 下载只接受已核验 HTTPS 域名、无非预期跳转；校验 DNS/私网目标、
  读取超时、流式大小上限及 MIME，不允许 SSRF。
- 解码后尺寸/像素检查、重新编码及缩略图，删除多余元数据；内容审核未过不发布。
  画面事实一致性不能单靠文件格式证明；真实评测需另记人工核对结果。
- 通过认证 fetch/blob 加载本人图片，私有缓存控制，注销后清缓存及 object URL；
  原始 Provider URL 和 API Key 不下发前端。
- 429/网络失败有界退避；401/403/配额不足暂停。
  对供应商可能已接收的 timeout/5xx，先按 job ID/幂等契约核验；
  如果 API 无法核验，保持 UNKNOWN 并阻止重新扣费，不能承诺 exactly-once 外部请求。
- 配额预留在发请求前持久化；记录不确定请求，不因重启、删图或换页面退回请求预算。
  实际费用无法确定时标 UNKNOWN，不按假设价格伪造。

真实 Provider 验收分两步：

1. 在独立已授权图像配置和明确小额硬预算下，先做 1 个虚构场景烟测，
   保存 model/provider/request ID、返回图片哈希/尺寸、阶段耗时、
   私有存储/授权读取/越权拒绝记录。无凭据/调用权限/预算则 BLOCKED。
2. 经预算条件满足后，按附件做 20～30 个虚构中文生活场景，评价语义一致性、
   失败、延迟及审核，不重放成功结果浪费额度。不能用一个烟测冒充规模验收。

阶段门：Mock 单独 PASS 不使 B 的真实验收 PASS。若 Provider 阻塞，
归档 BLOCKED 原因；可按附件保留后续 Mock UI 开发证据，但不得称已越过真实验收门。

## 6. 迁移、回滚与阶段证据制度

实施前在独立验收库做备份与恢复演练；生产数据迁移保持未执行状态。
所有 migration 以增量/幂等方式记录版本，先验证旧数据，再创建唯一约束。
旧 BLOB 不自动删除；需要转存时走可重放复制、校验、关联成功后再评审清理。
回滚优先关闭 V0.3 特性与 Worker，读取旧接口；不使用 DROP TABLE 或恢复旧库覆盖新原始数据。
schema 回退不强制删列，回滚脚本只作用验收副本，未关联资产清理有范围/保留期/预览。

每阶段必须独立保存：

| 交付 | 要求 |
| --- | --- |
| 文件清单 | 新增/修改、原因、影响、git diff/源码 hash；嵌套仓库单列 |
| 测试 | 命令、工作目录、环境、时间、退出码、失败及修复后的日志 |
| API 模式 | 明确 MOCK / REAL，供应商、模型、请求 ID、预算账本；真图文件哈希 |
| 页面 | 同尺寸前后、异常/空/撤权、五视口；无 UI 变更时写清基线范围 |
| 数据 | schema/迁移/恢复与唯一约束实查，不收录原始用户数据或秘密 |
| 风险 | P0/P1、NOT TESTED/BLOCKED/遗留问题，下一阶段门禁 |
| 独立日志 | 遵守 DEVELOPMENT_LOG_POLICY，更新索引；不覆盖历史失败 |

阶段状态采用 PASS / FAIL / BLOCKED / NOT TESTED / PARTIAL；
BLOCKED_PROVIDER 等只是原因码。T01～T24 的新验收当前均 NOT TESTED。
最终通过必须同时满足原始规格第 12 节，不能用本轮基线 174 项通过替代最终 DoD。
