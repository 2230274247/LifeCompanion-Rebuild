## 4. 按风险排序的具体发现

### F01｜P0：结算唯一键不能落实“同用户、同业务日、同槽最多一条”

`app/moments.py:259` 的结算 ID 基于带时区的结束时间字符串。
现有唯一约束是 `(user_id,window_start,window_end)` 与 `(user_id,window_end)`，
没有 local_date、policy_version，也没有 V0.3 所需的业务日唯一约束。
实测 Hong Kong→UTC 后，2026-11-04 上午槽出现两条不同 UTC 范围的结算。
这证明重复结算缺口；本轮没有触发生图，不能声称已发生重复扣费。

处理：业务日/slot 唯一索引、UTC 区间与策略快照；时区变更设生效边界，
不重置已结算槽位；进程并发与数据库约束共同验证。

### F02｜P1：既有窗口不符合默认方案 A

`app/moments.py:22` 默认 11:00/17:00/23:00；
`schedule` 将前一天最后窗口结束作为上午起点。
复现实测 11 月 4 日上午始于 11 月 3 日 23:00。
把 ends 简单改成 `11:00,16:00,00:05` 还会被有序时间校验拒绝，
且会混淆事件窗口与执行延时。

处理：按文档 A，00:00–11:00、11:00–16:00、16:00–次日00:00，
晚间次日00:05以后结算，回忆业务日期归前一日。旧设置不静默重写。

### F03｜P1：通用生活事件聚合不足

`app/memory.py:426` 的通用事件 key 取规范化摘要哈希，
`contextual_event` 仅覆盖特定指代/手动记忆语句。
同一次跑步的两种表述实测获得不同 key。
P04 的 DUPLICATE_EVENT 质量门存在，但不等于候选来源已完整聚合；
该回放未调用模型，不能断言模型一定会重复选中。

处理：在候选层聚合有共同事实、日期、来源关联的同一事件；
保留 source IDs，测试“同一次多说”和“同日两次真跑步”均不误处理。

### F04｜P1：损坏图像可通过头部校验

`app/moments.py:403` 的生成结果仅通过 PNG/JPEG magic bytes 判断格式。
用 MockTransport 返回 20 字节伪 PNG，真实函数返回 image/png，没有拒绝损坏内容。

处理：完整解码并重新编码，验证像素/尺寸/解压上限，移除不必要元数据，
生成缩略图与 SHA-256；任何失败均不发布。

### F05｜P0 验收条件：尚无独立 Kolors 接口与授权配置

现有生成器使用智谱聊天凭据及 CogView，不是 Kolors。
限定扫描的两个工作树配置文件未发现已配置的 Kolors / SiliconFlow 图像凭据；
canonical 的 IMAGE_PROVIDER_API_KEY 为空。只检查变量存在性，没有保存密钥值。
这不证明用户没有供应商账号或浏览器中的凭据。

真实供应商 endpoint/schema、账户可用模型、配额、费用、请求幂等能力、
数据政策和输出许可尚未完成核验。官方文档在线检索未获得可引用正文，
浏览器读取已打开文档也因超时未完成。文档 URL 本身不是当前可调用证明。

当前真实生图验收为 **BLOCKED**（原因码 BLOCKED_PROVIDER）。
没有调用旧聊天 Key 生图，没有自动选择收费替代模型，没有将任何私聊发给供应商。

### F06｜P1：私有媒体与发布链路尚未完成

目前 BLOB+本人 JSON 访问具备一定隔离，但缺少独立媒体 ID、缩略图、
尺寸/哈希、输出审核记录、image job ID、供应商任务 ID、租约和分步发布恢复。
图片存储成功与回忆发布成功不能视为一个结果。
已有 unknown 禁止重发的行为值得保留，不能为了“自动恢复”盲目重试生成请求。

### F07｜P1：前端尚未满足图片优先与用户管理验收

`Life/Moments.tsx:53` 的列表仅显示时间/文字/状态；
详情 `:150` 用原始 img，没有接入既有缩放查看器、完整图片失败回退。
删除为直接 mutation，缺少二次确认；隐藏、反馈不符实际、缩略图、
按业务日分组和媒体下载链路尚待实现。
当前项目有日期筛选；不能宣称已有独立日历并“完成适配”。
