# V0.2.3 对话与来源规范

本地整改，默认保持原有授权。真实业务成功只由服务端回执确认。

- 提醒：明确要求才调度；完整请求直接创建；不完整请求只问缺项，以 2–3 个时间/日期
  Chip 加“其他时间/日期”补充；最后一项选完立即调用服务端幂等提交。不得再展示已知
  日期、提前量、时区输入框。无主动通知授权时给出授权入口，不偷偷启用。
- 事件时刻和提醒时刻分别显示；相对日由服务器当前时间和 IANA 时区计算。
  地点能明确映射时区时用事件地；否则用账号时区，明确 IANA 输入优先。
- 已创建/已取消提醒保留“查看提醒”实体入口；“查看原对话”单独进入来源。
- 状态：needs_input → ready_to_confirm → creating → scheduled / unknown；
  cancelled / completed 是业务终态。unknown 只核对，不重复提交。
- 聊天历史、事实、计划、已发生事件、衍生回忆分开显示；“明天带 U 盘”可以是记忆中的
  未来计划，但不自动变成已发生事件或已创建提醒。
- 跨会话回答须以 owner 范围内持久记录为证据，保留“绿色，不是银色”限定；多个来源各有
  独立业务链接，查不到时明说，不能把上次模型回复作为证据。
- 回忆调度初始关闭。05–11 / 11–17 / 17–23 只是配置提议；23–05 明确归入下一早窗。
  午晚执行时刻需用户明确保存设置后才生效。无图提供商则显示待生成，不能用占位图冒充。

验收结果见 development-log/V023_ACCEPTANCE_MATRIX.md；此规范不代表所有场景已通过。
