## 1. 实施假设与边界

1. 技术栈固定为**原生 Kotlin + Jetpack Compose + Material3**，不引入 Flutter / React Native /
   Capacitor；`minSdk` / `targetSdk` / Compose BOM 在 P1 固化。
2. 首版范围 = 核心闭环（登录 / 流式聊天 / 私有回忆 / 提醒 / 时刻）+ V0.3 协作全量
   （好友 / 空间 / 共享回忆 / grants / 直接消息 / 共享状态与可用时段 / 通知 / 关怀转达）。
3. 后端边界为**仅复用现有网关 API**（`:3001` 的 `/api` 与 `/life-api`），不改 LibreChat 与
   life-core 源码；除非 P0 探针证明「纯复用」在认证 / 续期上不可行，才回到决策点做最小、
   有测试背书的边界调整，并走补丁归档 + 验收日志流程。
4. 身份沿用 LibreChat HS256 JWT → `life_user_id` → Memos 映射，不新增独立身份服务、不引入 SSO。
5. 界面方向采用 Meta Muse 的陪伴式消息心智模型 + 拾光雾青苔绿品牌，把既有的「大胆动效」
   收敛为克制的微动效；Otis 作为应用内陪伴头像。
6. 移动端差异化能力（OS 推送、离线队列、深链接、相册 / 麦克风权限）单独成阶段；
   不把「站内通知」冒充「设备送达」，不把 WebView 页面冒充原生 APK。
7. 工程位于 `apps/android/`（独立 Gradle 工程），绝不修改 `products/librechat-custom` 与
   `products/memos-custom` 上游源码；每个阶段按 `GIT_WORKTREE_POLICY` 独立提交并补中文验收日志。

## 2. 关键技术结论与前置风险

本次规划已核实：

- LibreChat `POST /api/auth/login`（邮箱 + 密码）返回 `{ token, user }`，`token` 即 life-core
  也认的 HS256 access JWT；但登录中间件链含 `requireSameOrigin`、登录限流、`requireLocalAuth`，
  刷新 `POST /api/auth/refresh` 为 Cookie 会话机制。
- 聊天流式为 SSE；具体 ask / 消息端点与分段形态需 P0 实测确认。
- life-core 公开路由由网关 `server.mjs` 白名单精确放行，内部接口与 `X-Internal-Token` 不出网。

由此确定的最高风险（必须在 P0 验证）：**原生无 Origin / Cookie 请求能否通过登录与续期**。
若不能，P0 产出明确的「可复用边界 vs 需最小调整」结论，交负责人决策，不擅自破坏
「仅复用现有 API」约束。

### P0 —— API 探针（不建 UI）

完成定义：产出「Android 可消费 API 清单 + 认证策略结论」，验证四件事：

1. 登录：原生无 Origin 请求是否通过 `requireSameOrigin`，`/api/auth/login` 返回 access JWT。
2. 续期：无 Cookie 下 `/api/auth/refresh` 能否续期；否则定「短会话重登」策略。
3. 流式：SSE ask 端点请求 / 响应形态（headers、分段、结束标记、超时）。
4. 可达性：life-core 全路由经网关在真机 / 模拟器下可达，白名单逐条对得上。

验收：用 OkHttp 脚本或 curl 对网关 `:3001` 实发登录 / 刷新 / 流式请求，记录状态码、头与分段。
结论用 PASS / BLOCKED，BLOCKED 时附「最小边界调整」候选与理由，交负责人决策。
阶段门：认证 / 续期结论未定，P1 不开始。

### P1 —— 骨架 + 认证

完成定义：可编译安装的空 APK，登录成功并安全持有 access token，401 自动处理（刷新或重登），
登出清除本地会话与缓存。

| 计划变更 | 新增 / 复用理由 |
| --- | --- |
| `apps/android/` 工程、`build.gradle(.kts)`、`gradle/libs.versions.toml` | 独立原生工程，固定 Compose BOM / 版本目录 |
| Hilt DI、Retrofit + OkHttp、kotlinx.serialization、DataStore、EncryptedSharedPreferences / Keystore | 按架构决策；安全存储用系统密钥加密，不落明文 token |
| 登录页 + `AuthRepository` + token 拦截器 | 复用现有 `/api/auth/login`；拦截器注入 `Authorization` 并处理 401 |

验收：真机 / 模拟器登录、token 加密落盘、冷启动恢复会话、登出后不可再访问私密路由。
安全存储不得以明文或 SharedPreferences 保存 access / refresh token。
