## 目标与固定约束

实现长期记忆、语义泛化、证据回答、意图/联网/提醒路由，以及模糊复杂回顾。以可追溯与可测量方式减少漏查和无依据回答，不承诺任意输入100%召回或绝对零幻觉。

- 禁止关键词、BM25、静态同义词或字面匹配召回兜底。用户/权限/日期等结构化筛选允许；不以关键词正则替代新语义路由。
- 模型权重只用H盘本地既有缓存，不下载到C盘。
- 保留LibreChat聊天组件、Memos官方API、提醒草稿/幂等/权限机制。
- 不触碰Silver-economy，不覆盖其他工作树、用户改动和数据库。
- 各阶段仅通过`scripts/git/checkpoint.ps1`显式路径提交，不推送。
- 独立上游代码需独立检查点及`patches/`归档；不把嵌套仓库源码遗漏于交付。
- 数据库新增结构先在临时合成数据库验证；真实库变更前独立备份。运行数据和凭据只留gitignored运行目录。

## 方案：一次请求如何运行

1. 认证取得用户身份和时区；用户原话持久化后才能执行有副作用的业务。
2. 已配置LLM结合当前日期、用户原话和有限用户上下文，输出严格结构化任务：普通问答、主题记忆、事件概览、提醒查询、提醒准备、联网需求；支持有界多意图。
3. 后端校验任务类型/数量/日期/长度，不接受模型指定用户、权限、SQL、URL或执行成功状态。规划不可用单独返回，不用关键词猜意图。
4. 主题查询用现有BGE和重排，允许全历史；时间概览按授权事件时间查询并分页，不经过内容相似度阈值。展开语义查询是检索假设，不是事实。
5. 返回有来源的证据包：用户原话关联、事件时间/记录时间、覆盖数/总数/截断/更多结果、工具执行结果。未确定事件日期不得伪造日期。
6. LLM基于证据回答，区分个人事实、当前用户陈述、通用知识、外部资料与主观判断。服务失败、无命中和不完整分别表达。
7. 提醒复用既有草稿与真实回执，联网只有工具可用且真正执行时才声称已搜索；写入保持幂等和unknown/reconcile。

## 数据与安全合同

- 授权原话台账是证据和补建入口；提炼记忆不能替代原始来源，聊天保存也不代表提炼成功。
- 记录时间与事件时间分别表示；未知发生时间不按保存日期擅自宣称。
- 撤回或纠正后，应使受影响原话的派生向量/摘要失效；避免补建把撤回资料复活。
- 不无限返回全部历史。具体查询传少量证据；概览分页并明确本次覆盖，不把top-k当完整历史。
- 上游模型与工具输出视为不可信数据；不会授权跨用户或任意网络/数据库执行。
- 不增加新框架替换完整平台；先复用现有组件。超过预算可返回不完整或不可用，不隐瞒状态。
